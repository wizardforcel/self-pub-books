# 第 24 章 内存管理：虚拟内存、堆与内存映射文件

> **章内定位**：对应《Windows 核心编程》第 III 部分“内存管理”（第 13–18 章：Windows 内存架构、探索虚拟内存、使用虚拟内存、线程栈、内存映射文件、堆）。PowerShell 脚本通常不需要直接管理虚拟内存，但在**跨进程读取内存**、**大文件的内存映射处理**、**非托管缓冲区的手动分配**这些场景下，Win32 内存 API 是唯一路径。第 20.4 节的结构体封送已经涉及 `AllocHGlobal`，本章将其放入完整的虚拟内存语义中。
>
> 一句话分清三种“内存”：**`AllocHGlobal` 是“进程堆上的一小块”；`VirtualAlloc` 是“直接向操作系统要地址空间”；`MemoryMappedFile` 是“把文件/共享内存映射成地址空间”。**

## 24.1 虚拟内存查询与提交：`VirtualQuery` / `VirtualAlloc`

Windows 给每个进程一个“虚拟地址空间”。这个空间不是“一上来就全部可用”的，而是按“页”划分，有三种状态：

| 状态 | 常量 | 含义 |
|---|---|---|
| **空闲** | `MEM_FREE`（`0x10000`） | 这块地址还没被占用 |
| **保留** | `MEM_RESERVE`（`0x2000`） | 地址被“预留”了，但还没给物理存储/页文件 |
| **提交** | `MEM_COMMIT`（`0x1000`） | 地址已分配，可以真正读写 |

理解“保留 vs 提交”，是理解本章的关键：**保留 = 占了个位；提交 = 真的能用了。**

### `VirtualQuery`：查某个地址所在区域的“户口”

`VirtualQuery` 告诉你“某个地址落在哪个区域、是什么状态、什么保护属性、什么类型”。它填充一个 `MEMORY_BASIC_INFORMATION` 结构：

```csharp
[StructLayout(LayoutKind.Sequential)]
public struct MEMORY_BASIC_INFORMATION {
    public IntPtr BaseAddress;
    public IntPtr AllocationBase;
    public uint AllocationProtect;
    public UIntPtr RegionSize;
    public uint State;
    public uint Protect;
    public uint Type;
}
```

用法（用 `IntPtr` 接收结构体，避免 PowerShell 的 `ref/out` 结构体封送问题）：

```powershell
$M = [System.Runtime.InteropServices.Marshal]
$mbiSize = $M::SizeOf([type][MEMORY_BASIC_INFORMATION])
$mbiPtr = $M::AllocHGlobal($mbiSize)

try {
    $q = [MemTest]::VirtualQuery($address, $mbiPtr, [UIntPtr]::new($mbiSize))
    $mbi = $M::PtrToStructure($mbiPtr, [type][MEMORY_BASIC_INFORMATION])
    "State: 0x{0:X}" -f $mbi.State
    "Protect: 0x{0:X}" -f $mbi.Protect
    "Type: 0x{0:X}" -f $mbi.Type
    "RegionSize: $($mbi.RegionSize.ToUInt64())"
}
finally {
    $M::FreeHGlobal($mbiPtr)
}
```

实测（对一块 `VirtualAlloc` 出来的地址查询）得到：

- **`State = 0x1000`**（`MEM_COMMIT`，已提交）；
- **`Protect = 0x4`**（`PAGE_READWRITE`，可读可写）；
- **`Type = 0x20000`**（`MEM_PRIVATE`，私有内存）；
- **`RegionSize = 4096`**（一个页）。

`Type` 的取值也值得记一下：`MEM_IMAGE`（`0x1000000`，来自映像/DLL）、`MEM_MAPPED`（`0x40000`，来自映射文件）、`MEM_PRIVATE`（`0x20000`，进程私有）。

### `VirtualAlloc`：`MEM_RESERVE` / `MEM_COMMIT` 与保护属性

`VirtualAlloc` 既保留、又提交：

```csharp
[DllImport("kernel32.dll", SetLastError=true)]
public static extern IntPtr VirtualAlloc(IntPtr addr, UIntPtr size,
    uint allocType, uint protect);
```

常用组合：

| 参数 | 含义 |
|---|---|
| `MEM_COMMIT \| MEM_RESERVE`（`0x3000`） | 一步到位：保留并提交 |
| `MEM_RESERVE`（`0x2000`） | 只保留地址，不提交 |
| `MEM_COMMIT`（`0x1000`） | 提交已保留的地址 |
| `PAGE_READWRITE`（`0x04`） | 可读可写 |
| `PAGE_EXECUTE_READ`（`0x20`） | 可执行只读（放代码常用） |
| `PAGE_NOACCESS`（`0x01`） | 不可访问（保护页） |

```powershell
$size = [UIntPtr]::new(4096)
# 保留 + 提交，一页，可读写
$ptr = [MemTest]::VirtualAlloc([IntPtr]::Zero, $size, 0x3000, 0x04)

if ($ptr -eq [IntPtr]::Zero) {
    $code = [System.Runtime.InteropServices.Marshal]::GetLastWin32Error()
    throw "VirtualAlloc 失败：$([System.ComponentModel.Win32Exception]::new($code).Message)"
}
```

实测：返回非零地址；用 `Marshal.WriteInt32` 写入 `123456`，`ReadInt32` 读回来也是 `123456`。

### `VirtualFree`：`MEM_RELEASE` 与 `MEM_DECOMMIT`

释放也分两种“退法”：

```csharp
[DllImport("kernel32.dll", SetLastError=true)]
public static extern bool VirtualFree(IntPtr addr, UIntPtr size, uint freeType);
```

- **`MEM_RELEASE`（`0x8000`）**：把“保留的地址”彻底还回去；调用时 `size` 必须传 `0`；
- **`MEM_DECOMMIT`（`0x4000`）**：只“取消提交”，保留地址（以后还能再提交）。

```powershell
# 彻底释放（都必须传 size=0）
[MemTest]::VirtualFree($ptr, [UIntPtr]::Zero, 0x8000)   # 实测 True
```

**务必记住**：`VirtualAlloc` 分配的内存**不受 GC 管理**，不 `VirtualFree` 就是“进程级内存泄漏”；所以分配的指针要放在 `try/finally` 里释放（和第 20 章的 `FreeHGlobal` 一个道理）。

### 一个完整的“分配 → 读写 → 查询 → 释放”例子

```powershell
$M = [System.Runtime.InteropServices.Marshal]
$size = [UIntPtr]::new(4096)

$ptr = [MemTest]::VirtualAlloc([IntPtr]::Zero, $size, 0x3000, 0x04)
try {
    $M::WriteInt32($ptr, 123456)
    "读回：$($M::ReadInt32($ptr))"        # 123456（实测）

    # 查它的“户口”
    $mbiPtr = $M::AllocHGlobal($M::SizeOf([type][MEMORY_BASIC_INFORMATION]))
    try {
        [void][MemTest]::VirtualQuery($ptr, $mbiPtr, [UIntPtr]::new($M::SizeOf([type][MEMORY_BASIC_INFORMATION])))
        $mbi = $M::PtrToStructure($mbiPtr, [type][MEMORY_BASIC_INFORMATION])
        "状态：0x{0:X}，保护：0x{1:X}" -f $mbi.State, $mbi.Protect
    }
    finally { $M::FreeHGlobal($mbiPtr) }
}
finally {
    [void][MemTest]::VirtualFree($ptr, [UIntPtr]::Zero, 0x8000)
}
```

### 24.1 小结

1. **虚拟地址有三种状态**：`MEM_FREE`（空闲）、`MEM_RESERVE`（保留）、`MEM_COMMIT`（提交）。
2. **`VirtualQuery`** 用 `MEMORY_BASIC_INFORMATION` 查“地址的户口”（State/Protect/Type/RegionSize）。
3. **`VirtualAlloc`** `MEM_COMMIT|MEM_RESERVE`（`0x3000`）一步到位；保护属性 `PAGE_READWRITE`（`0x04`）等。
4. **`VirtualFree`**：`MEM_RELEASE`（`0x8000`，size 传 0，彻底还）或 `MEM_DECOMMIT`（`0x4000`，只取消提交）；**放 `finally`**。

## 24.2 内存映射文件：`CreateFileMapping` / `MapViewOfFile`

“内存映射文件”把**磁盘文件的一部分**或**页文件的一部分**映射到进程地址空间。你读写“映射视图”，就是在读写文件/共享内存——**不需要 `ReadFile` / `WriteFile`**。

它有两个典型用途：

1. **大文件高效随机访问**：把大文件映射进来，按偏移读写，系统按页“按需”调入；
2. **跨进程共享内存**：用“页文件 + 命名映射对象”，多个进程映射同一个名字，就看到同一块内存。

### `CreateFileMapping(INVALID_HANDLE_VALUE)`：基于页文件的共享内存

```csharp
[DllImport("kernel32.dll", CharSet=CharSet.Auto, SetLastError=true)]
public static extern IntPtr CreateFileMapping(
    IntPtr file, IntPtr attrs, uint protect,
    uint maxHigh, uint maxLow, string name);

[DllImport("kernel32.dll", SetLastError=true)]
public static extern IntPtr MapViewOfFile(
    IntPtr mapping, uint access, uint offsetHigh, uint offsetLow, UIntPtr bytes);
```

- **`file = INVALID_HANDLE_VALUE`（`-1`）**：表示“不基于磁盘文件”，而是用**页文件**做后盾——这就是“共享内存”；
- **`protect = PAGE_READWRITE`（`0x04`）**：映射对象可读写；
- **`maxHigh` / `maxLow`**：映射对象的大小（高 32 位 / 低 32 位）；
- **`name`**：命名后可以跨进程用同一个名字打开。

映射视图：

```powershell
$INVALID_HANDLE_VALUE = [IntPtr]::new(-1)
$mapping = [MemTest]::CreateFileMapping($INVALID_HANDLE_VALUE, [IntPtr]::Zero, 0x04, 0, 4096, 'Local\MySharedMem')

# FILE_MAP_ALL_ACCESS = 0xF001F（简化为 FILE_MAP_READ|WRITE 也可）
$view = [MemTest]::MapViewOfFile($mapping, 0xF001F, 0, 0, [UIntPtr]::new(4096))

try {
    # 对 $view 用 Marshal 读写
}
finally {
    [MemTest]::UnmapViewOfFile($view)
    [MemTest]::CloseHandle($mapping)
}
```

要点：

- **`MapViewOfFile` 返回“视图基地址”**；你往后读写这个地址；
- **`UnmapViewOfFile`** 解除映射；**`CloseHandle`** 关闭映射对象句柄；
- **命名映射（`Local\` / `Global\`）** 才能跨进程共享；不命名的只能当前进程/句柄继承用。

### 托管替代：`MemoryMappedFile`

. NET 提供了 `System.IO.MemoryMappedFiles.MemoryMappedFile`，把上面那套 Win32 流程封装成了托管 API：

```csharp
// 创建/打开一个命名的“共享内存”映射对象
var mmf = MemoryMappedFile.CreateNew("Local\\MySharedMem", 4096);
var view = mmf.CreateViewAccessor();
```

常用工厂：

| 方法 | 用途 |
|---|---|
| `CreateNew(name, capacity)` | 新建一个“页文件后盾”的映射对象（共享内存） |
| `CreateOrOpen(name, capacity)` | 存在就打开、不存在就新建 |
| `CreateFromFile(path, ...)` | 基于磁盘文件映射 |

**我们实测确认**：`CreateNew('Local\PSDeepDiveMMFTest', 1024, ReadWrite)` → `CreateViewAccessor()` → `Write(0, [byte]65)` → `ReadByte(0)` 得到 `65`。

一个最小例子：

```powershell
$mmf = [System.IO.MemoryMappedFiles.MemoryMappedFile]::CreateNew(
    'Local\PSDeepDiveMMFTest', 1024,
    [System.IO.MemoryMappedFiles.MemoryMappedFileAccess]::ReadWrite)

$view = $mmf.CreateViewAccessor()
try {
    $view.Write(0, [byte]65)          # 写一个字节
    "读回：$($view.ReadByte(0))"      # 65（实测）
}
finally {
    $view.Dispose()
    $mmf.Dispose()
}
```

> **注意**：`MemoryMappedFile.CreateFromFile` 在 PowerShell 里**很容易“重载错位”**——我们实测就遇到了“把 `1024` 当成了 `FileMode`”的报错。PowerShell 对重载的解析不如 C# 精确。**建议：要么用 `CreateNew` / `CreateOrOpen`，要么显式写成 C# 方法封装**（第 21 章的经验）。

### 一个托管版的最小例子（实测）

上面那段就是实测跑通的完整代码：**创建（`CreateNew`）→ 视图（`CreateViewAccessor`）→ 写（`Write`）→ 读（`ReadByte`）→ 释放（`Dispose`）**。

它的“跨进程”用法是：

- 进程 A：`CreateNew('Local\MySharedMem', 4096)` 写数据；
- 进程 B：`CreateOrOpen('Local\MySharedMem', 4096)` 读同一名字的数据；
- 两边映射的是**同一块页文件内存**。

**什么时候用托管版、什么时候用 Win32？**

- **日常“共享一块内存/映射一个大文件” → `MemoryMappedFile`**（更安全、自动管理句柄）；
- **需要精细控制保护属性、视图偏移、或与原生代码共享对象 → `CreateFileMapping` / `MapViewOfFile`**。

### 24.2 小结

1. **内存映射**把文件/页文件映射进地址空间，读写映射视图 = 读写文件/共享内存。
2. **`CreateFileMapping(INVALID_HANDLE_VALUE, ..., name)`** 做“页文件后盾”的共享内存；**`MapViewOfFile`** 拿视图基地址，`UnmapViewOfFile` + `CloseHandle` 收尾。
3. **托管 `MemoryMappedFile`**：`CreateNew` / `CreateOrOpen` / `CreateFromFile`；`CreateFromFile` 在 PowerShell 里**易重载错位**，优先 `CreateNew`/`CreateOrOpen` 或封装进 C#。
4. 命名映射（`Local\`/`Global\`）才能跨进程。

## 本章总结

第 24 章把“内存”讲成了两层：

- **24.1 虚拟内存**：三种状态（Free/Reserve/Commit）；`VirtualQuery` 查户口（State/Protect/Type/RegionSize）；`VirtualAlloc` 用 `0x3000` 一步提交；`VirtualFree` 用 `MEM_RELEASE`/`MEM_DECOMMIT`；**手动分配的内存不受 GC 管，`finally` 释放**。
- **24.2 内存映射文件**：`CreateFileMapping`（`INVALID_HANDLE_VALUE` = 页文件共享内存）+ `MapViewOfFile` + `UnmapViewOfFile`/`CloseHandle`；托管 `MemoryMappedFile` 的 `CreateNew`/`CreateOrOpen` 更安全（`CreateFromFile` 注意重载错位）。

一句话记住全章：**“`AllocHGlobal` 是堆上一小块，`VirtualAlloc` 是直接要地址空间，`MemoryMappedFile` 是把文件/共享内存映射成地址；手动分配的内存一律 `finally` 释放。”**
