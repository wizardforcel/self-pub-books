# 第 28 章 图形与文本输出：GDI 与设备上下文

> **章内定位**：对应《Windows程序设计》的“图形”部分（Petzold 第 5 版第 13–18 章：GDI 绘图、位图、调色板；王艳平版第 4 章“Windows图形界面”）。PowerShell 中图形输出的首选是 **WinForms 的 `System.Drawing`（GDI+ 托管封装）**，而不是裸 GDI32。本章的价值在于：理解 **`HDC`（设备上下文）、GDI 对象（画笔/画刷/字体）和双缓冲的底层机制**，以便在 `System.Drawing` 不够用时（如需要更细粒度的 GDI 控制或与遗留本机绘制代码交互）能够下沉到 `gdi32.dll`。
>
> 一句话先立规矩：**画图优先 `System.Drawing`，裸 GDI 留给“窗口截图”和“遗留兼容”。**

## 28.1 设备上下文：`GetDC` / `CreateCompatibleDC` 与 `BitBlt`

GDI 的世界里，一切绘制都发生在“**设备上下文（Device Context，`HDC`）**”上。`HDC` 是 GDI 绘制的“画布句柄”——它可以是屏幕、窗口客户区、内存位图、打印机……

### `HDC`：GDI 绘制的“画布”

简化的心智模型：

- **`HDC` 是一个“画布”**：你往里画线、填充、写字；
- 画布可以来自“屏幕”“窗口”“内存位图”等；
- **`HDC` 也是句柄**（`IntPtr`）：用完要“还”（Release/Delete），不能 `[int]`。

### `GetDC` / `ReleaseDC`：拿到屏幕/窗口的 DC

```csharp
[DllImport("user32.dll")] public static extern IntPtr GetDC(IntPtr hWnd);
[DllImport("user32.dll")] public static extern int ReleaseDC(IntPtr hWnd, IntPtr hDC);
```

- **`GetDC([IntPtr]::Zero)`**：拿**整个屏幕**的 DC（实测返回非零）；
- **`GetDC($hwnd)`**：拿某个窗口**客户区**的 DC；
- **`ReleaseDC` 必须配对**：它是从“公共 DC 缓存”里借的，不还就会耗尽（Windows 有数量上限）。

### `CreateCompatibleDC` / `DeleteDC`：内存 DC

```csharp
[DllImport("gdi32.dll")] public static extern IntPtr CreateCompatibleDC(IntPtr hdc);
[DllImport("gdi32.dll")] public static extern bool DeleteDC(IntPtr hdc);
```

**内存 DC** 是一块“在内存里的画布”——你在上面画，看不见屏幕，但可以：

- 把各种图“合成”好再一次性贴到屏幕（**双缓冲**，避免闪烁）；
- 作为 `BitBlt` 的“目标”，把屏幕/窗口“截”进来（**截图**）。

`CreateCompatibleDC($screenDC)` 创建一个“和屏幕兼容”的内存 DC；用完 `DeleteDC`。

### `BitBlt`：DC 之间的位块传输（窗口截图）

```csharp
[DllImport("gdi32.dll")] public static extern bool BitBlt(
    IntPtr dest, int x, int y, int w, int h,
    IntPtr src, int srcX, int srcY, uint rop);
```

参数含义：

- **`dest` / `src`**：目标 DC / 源 DC；
- **`w` / `h`**：拷贝的宽高；
- **`srcX` / `srcY`**：从源 DC 的哪个位置开始拷；
- **`rop`**：光栅操作码，**`SRCCOPY = 0x00CC0020`** 表示“直接拷贝”。

“窗口截图”的标准流程（我们实测 `BitBlt` 返回 `True`）：

1. `GetDC(hWnd)` / `GetDC(NULL)` 拿源 DC；
2. `CreateCompatibleDC(srcDC)` + `CreateCompatibleBitmap(srcDC, w, h)` + `SelectObject(memDC, bitmap)`；
3. **`BitBlt(memDC, 0, 0, w, h, srcDC, 0, 0, SRCCOPY)`**；
4. 用 `GetDIBits` 把内存位图读成 `byte[]`；
5. `SelectObject(memDC, oldBitmap)` 恢复、`DeleteObject(bitmap)`、`DeleteDC(memDC)`、`ReleaseDC(srcDC)`。

### `GetDIBits` 转回托管位图

`GetDIBits` 把“GDI 位图”按 DIB（Device-Independent Bitmap）格式读成字节数组，再交给 `System.Drawing.Bitmap` 构造：

```csharp
[DllImport("gdi32.dll")] public static extern int GetDIBits(
    IntPtr hdc, IntPtr hbm, uint start, uint lines,
    byte[] bits, ref BITMAPINFO bmi, uint usage);
```

**关键**：`BITMAPINFO` 里的 `biBitCount` 要设成 32（BGRA），`biHeight` 为负表示“自上而下”的行序——否则导出的图片会“上下颠倒”。这是 Windows 截图代码最经典的“翻转”坑。

> **PowerShell 里的更简单做法**：如果你只是想“截个图”，可以用 `System.Drawing.Graphics.CopyFromScreen()`（第 19 章已经加载了 `System.Drawing`）——一行就搞定，不用手搓 `BitBlt` + `GetDIBits`。**裸 GDI 的价值在于“理解机制”和“托管封装兜不住时的细粒度控制”。**

### 28.1 小结

1. **`HDC` 是绘制的画布（句柄）**；`GetDC`/`ReleaseDC`、`CreateCompatibleDC`/`DeleteDC` 必须配对。
2. **`CreateCompatibleDC`** 造内存画布；**`BitBlt`（`SRCCOPY=0x00CC0020`）** 在 DC 间拷贝，是“截图”的核心。
3. **`GetDIBits`** 把 GDI 位图读成 `byte[]`；注意 `biBitCount=32` 与 `biHeight` 正负带来的翻转。
4. **优先 `System.Drawing`**（`CopyFromScreen` 一行截图）；裸 GDI 用于理解与兜底。

## 28.2 GDI 对象与文本输出：`CreatePen` / `CreateSolidBrush` / `TextOut`

GDI 绘制不只靠 DC，还靠“**GDI 对象**”：画笔（`HPEN`）、画刷（`HBRUSH`）、字体（`HFONT`）。它们用 `Create*` 创建、用 `SelectObject` 选入 DC、用 `DeleteObject` 删除。

### GDI 对象：画笔/画刷/字体

```csharp
[DllImport("gdi32.dll")] public static extern IntPtr CreatePen(int style, int width, uint color);
[DllImport("gdi32.dll")] public static extern IntPtr CreateSolidBrush(uint color);
```

- **`CreatePen(样式, 宽度, 颜色)`**：画线用的“笔”；
- **`CreateSolidBrush(颜色)`**：填充用的“实心刷”。

我们实测：在内存 DC 上 `CreateSolidBrush(0x0000FF)` 填充 20×20 的矩形后，`GetPixel(5,5)` 读到 **`0x0000FF`**——这是“红色”（见下面的颜色格式）。

### `SelectObject` / `DeleteObject`：选入与恢复

```csharp
[DllImport("gdi32.dll")] public static extern IntPtr SelectObject(IntPtr hdc, IntPtr obj);
[DllImport("gdi32.dll")] public static extern bool DeleteObject(IntPtr obj);
```

用法是“**选入 → 用 → 选回旧对象 → 删除**”：

```powershell
$oldPen   = [GdiTest]::SelectObject($memDC, $pen)
try {
    # 用 $pen 画线……
}
finally {
    [void][GdiTest]::SelectObject($memDC, $oldPen)   # 必须先恢复旧对象
    [void][GdiTest]::DeleteObject($pen)              # 再删除
}
```

**为什么必须先恢复？** 因为“GDI 对象在使用时不能被删除”。如果某个对象还“选在 DC 里”，你 `DeleteObject` 它会失败/泄漏。**顺序错了，对象就一直挂在 DC 上。**

### 颜色格式 `0x00BBGGRR`

GDI 的 `COLORREF` 是 **`0x00BBGGRR`**（**不是** RGB！）：

- 最低字节 = 红（RR）；
- 中间字节 = 绿（GG）；
- 高字节（除最高 0） = 蓝（BB）。

所以：

- 红色 = `0x0000FF`（R=FF，G=00，B=00）；
- 绿色 = `0x00FF00`；
- 蓝色 = `0xFF0000`。

这和 `System.Drawing.Color.R, G, B` 的“人类直觉顺序”正好相反，**写错顺序就会“红蓝互换”**——这是 GDI 新手的第一大坑。

### `TextOut` / `DrawText`

```csharp
[DllImport("gdi32.dll", CharSet=CharSet.Unicode)]
public static extern bool TextOut(IntPtr hdc, int x, int y, string s, int len);
```

`TextOut(dc, x, y, 字符串, 长度)` 在 DC 的 `(x,y)` 处写文本。实测返回 `True`。

更强大的 `DrawText` 支持“矩形内排版、对齐、换行”（需要传入 `RECT` 和格式标志，如 `DT_CENTER`、`DT_WORDBREAK`）。它和 `TextOut` 的关系，类似于“简单写字”与“文本框排版”。

> **提醒**：`TextOut` 写在**内存 DC** 上不会显示到屏幕；要显示，得把内存 DC 的内容再 `BitBlt` 到窗口/屏幕 DC，或者直接把 DC 换成窗口 DC。这也正是“双缓冲”的工作方式。

### 28.2 小结

1. **GDI 对象**：`CreatePen`（线）、`CreateSolidBrush`（填充）、字体；**选入 → 用 → 选回旧对象 → `DeleteObject`**。
2. **颜色是 `0x00BBGGRR`**（R 在最低字节），写反会“红蓝互换”。
3. **`TextOut`** 在 DC 上写字（`True` 实测）；**`DrawText`** 支持矩形内排版。
4. 内存 DC 上的绘制不显示；要显示得 `BitBlt` 回屏幕/窗口（双缓冲）。

第 28 章把“图形输出”讲到了 GDI 层：

- **28.1 设备上下文**：`HDC` 是画布；`GetDC`/`ReleaseDC`、`CreateCompatibleDC`/`DeleteDC` 配对；`BitBlt`（`SRCCOPY`）做截图；`GetDIBits` 转字节数组；**优先 `System.Drawing` 的 `CopyFromScreen`**。
