# 第 11 章 输入/输出与文件系统库

程序不与外界交互就没有意义：读取配置文件、把结果写到磁盘、在控制台打印日志、遍历目录下的所有文件……这些都属于 I/O（输入/输出）的范畴。

本章覆盖三个部分：

- 11.1 流式 I/O：`iostream`、格式化与操纵符，以及 `std::osyncstream` 的并发输出；
- 11.2 字符串流与 `spanstream`：在内存缓冲区上做流式格式化/解析；
- 11.3 文件系统库：`path`、目录遍历、文件状态查询、复制/删除/重命名。

核心原则依然是**选型而非 API 罗列**：什么时候用流式输出，什么时候用 `std::format`/`std::print`，什么时候用 `stringstream`，什么时候直接操作文件系统，每一节都会给出决策依据和反例。

> **工具约定**：示例以 C++20 为基线；`std::spanstream` 是 C++23 特性，`<filesystem>` 是 C++17 特性。涉及文件系统操作的示例会在当前目录或临时目录下创建文件，运行时注意权限。代码片段可用 `cxxsh` 单文件验证，放入真实项目时请套用第 7.7 节的 CMake + vcpkg 工程模板。

## 11.1 流式 I/O：`iostream`、格式化与操纵符

### 11.1.1 `iostream` 基础

`iostream` 家族是 C++ 最经典的 I/O 设施，核心思想是**流（stream）**：把数据看作一个连续的字节序列，用 `<<` 把数据“插入”到输出流，用 `>>` 从输入流“提取”数据。

标准库预定义了几个常用流对象：

| 流对象 | 含义 | 头文件 |
|---|---|---|
| `std::cin` | 标准输入（键盘） | `<iostream>` |
| `std::cout` | 标准输出（控制台） | `<iostream>` |
| `std::cerr` | 标准错误（控制台，无缓冲） | `<iostream>` |
| `std::clog` | 标准日志（控制台，有缓冲） | `<iostream>` |

```cpp
// iostream_basic.cpp
#include <iostream>
#include <string>

int main() {
    std::cout << "请输入你的名字： ";
    std::string name;
    std::cin >> name;              // 从标准输入读取一个词
    std::cout << "你好，" << name << "！\n";

    std::cerr << "这是一条错误信息\n";   // 标准错误，通常不被重定向
    std::clog << "这是一条日志信息\n";   // 标准日志
}
```

运行示例：

```
请输入你的名字： 张三
你好，张三！
这是一条错误信息
这是一条日志信息
```

`<<` 可以连续调用，像流水线一样把多个值送到输出流；`std::endl` 会换行并刷新缓冲区，而 `'\n'` 只换行不刷新，日常写作推荐用 `'\n'` 以避免不必要的刷新开销。

### 11.1.2 流状态与错误检测

流对象有内部状态，可以用来判断读写是否成功。常见状态检查：

- `stream.good()`：流处于正常状态；
- `stream.fail()`：发生可恢复错误（如读取失败、格式不匹配）；
- `stream.eof()`：到达文件末尾；
- `stream.bad()`：发生不可恢复错误（如底层设备损坏）。

```cpp
// stream_state.cpp
#include <iostream>
#include <string>

int main() {
    std::cout << "请输入一个整数： ";
    int x;
    std::cin >> x;

    if (std::cin.fail()) {
        std::cerr << "输入错误：你输入的不是一个整数\n";
        std::cin.clear();              // 清除错误标志
        std::cin.ignore(10000, '\n');  // 忽略本行剩余内容
        return 1;
    }

    std::cout << "你输入的整数是：" << x << '\n';
}
```

如果用户输入了非整数内容（如 "abc"），`std::cin >> x` 会失败，流进入 `fail` 状态，后续读取会一直失败，直到调用 `clear()` 清除状态并丢弃错误输入。

### 11.1.3 格式化操纵符（manipulators）

`<iomanip>` 提供了一组操纵符，用于控制输出格式，如宽度、填充字符、进制、浮点精度等：

```cpp
// iomanip_basic.cpp
#include <iostream>
#include <iomanip>
#include <string>

int main() {
    std::cout << std::setw(10) << std::setfill('*') << 42 << '\n';
    // 输出：********42（宽度 10，右对齐，前面补 *）

    std::cout << std::hex << 255 << '\n';   // 十六进制：ff
    std::cout << std::dec << 255 << '\n';   // 换回十进制

    std::cout << std::fixed << std::setprecision(2) << 3.14159 << '\n';  // 3.14
}
```

输出：

```
********42
ff
255
3.14
```

常用操纵符：
- `std::setw(n)`：设置下一次输出的字段宽度；
- `std::setfill(c)`：设置填充字符；
- `std::left` / `std::right`：左对齐/右对齐；
- `std::hex` / `std::dec` / `std::oct`：十六进制/十进制/八进制；
- `std::fixed` / `std::scientific`：定点/计数法浮点输出；
- `std::setprecision(n)`：浮点数有效数字或小数位数。

### 11.1.4 `std::osyncstream`：并发安全的输出（C++20）

多个线程同时向 `std::cout` 写入时，输出可能交错（一行里混杂两个线程的字符）。`std::osyncstream`（`<syncstream>`）把输出缓冲到本地，析构时一次性原子性地写到底层流，避免交错。

```cpp
// osyncstream_basic.cpp
#include <iostream>
#include <syncstream>
#include <thread>

void worker(int id) {
    std::osyncstream out(std::cout);
    out << "线程 " << id << " 正在工作\n";
    // out 析构时，整行原子性地写到 cout，不会和别的线程交错
}

int main() {
    std::thread t1(worker, 1);
    std::thread t2(worker, 2);
    t1.join();
    t2.join();
}
```

多次运行，每次输出都是完整的行，不会出现“线 程 1 2 正在工作”这种交错现象。

### 11.1.5 流式 I/O vs `std::format`/`std::print`

| 场景 | 推荐方式 | 原因 |
|---|---|---|
| 快速调试、简单打印 | `std::cout <<` | 最简单，无需额外头文件 |
| 需要精确格式控制（宽度、填充、进制） | `std::cout` + `<iomanip>` | 流式操纵符成熟 |
| 构造格式化字符串（日志、报表） | `std::format` / `std::print`（C++23） | `{}` 模板更清晰，类型安全 |
| 多线程并发输出 | `std::osyncstream` | 避免输出交错 |
| 频繁写入文件 | `std::ofstream` + 缓冲 | 避免 `endl` 引起的频繁刷新 |

**反例**：不要在循环里每次输出都用 `std::endl`，它会强制刷新缓冲区，显著降低写入性能；大多数情况下用 `'\n'` 即可。

## 11.2 字符串流与 `spanstream`

### 11.2.1 `std::stringstream`：内存中的流

`std::stringstream`（`<sstream>`）把一个 `std::string` 当成流来读写，常用于字符串与数值之间的转换，或者在内存中构造复杂字符串。

```cpp
// stringstream_basic.cpp
#include <iostream>
#include <sstream>
#include <string>

int main() {
    // 数字转字符串
    std::stringstream ss;
    ss << "温度：" << 36.5 << "℃，湿度：" << 60 << "%";
    std::string result = ss.str();
    std::cout << result << '\n';

    // 字符串解析成数字
    std::string input = "100 200.5 hello";
    std::stringstream parser(input);
    int a;
    double b;
    std::string c;
    parser >> a >> b >> c;
    std::cout << a << ", " << b << ", " << c << '\n';
}
```

输出：

```
温度：36.5℃，湿度：60%
100, 200.5, hello
```

`stringstream` 灵活，但每次 `str()` 都可能涉及字符串拷贝，且构造/析构有开销。在高性能场景下，更推荐直接用 `std::format` 或 `std::to_chars`（C++17，`<charconv>`）做数值转换。

### 11.2.2 `std::spanstream`：基于固定缓冲区的无分配流（C++23）

`std::spanstream`（`<spanstream>`）是 C++23 引入的，基于 `std::span` 固定缓冲区提供流式格式化/解析，**不发生堆分配**。适合嵌入式、内核、或对延迟敏感的场景：你预先准备一块缓冲区，把它包成 `span`，然后往里面写格式化内容，写满为止。

```cpp
// spanstream_basic.cpp
// 需要 C++23 编译器支持
#include <iostream>
#include <spanstream>
#include <span>
#include <vector>

int main() {
    char buffer[64];
    std::span<char> span_buf(buffer);

    std::spanstream ss(span_buf);
    ss << "Hello, " << "world" << "! Count = " << 42;

    std::cout << "内容：" << ss.view() << '\n';
    std::cout << "已写长度：" << ss.view().size() << '\n';
}
```

可能的输出：

```
内容：Hello, world! Count = 42
已写长度：21
```

`spanstream` 不会申请堆内存，如果内容超出缓冲区大小，写入会失败（进入 fail 状态）。它的 API 和 `stringstream` 类似，但更轻量、更可控。

### 11.2.3 选型建议

| 需求 | 推荐设施 | 备注 |
|---|---|---|
| 字符串与数值互转 | `std::stringstream` 或 `std::format`/`std::to_chars` | 性能敏感用 `to_chars` |
| 在内存中按流式方式构造字符串 | `std::stringstream` | 简单方便，但有拷贝开销 |
| 无堆分配的流式写入 | `std::spanstream`（C++23） | 嵌入式/低延迟场景 |
| 直接格式化到控制台 | `std::print` / `std::println`（C++23） | 无中间字符串，最简洁 |

## 11.3 文件系统库

### 11.3.1 `std::filesystem` 概览（C++17）

`<filesystem>` 是 C++17 标准化的文件系统库（源自 Boost.Filesystem），提供跨平台的路径操作、目录遍历、文件状态查询、复制/删除/重命名等功能。

核心组件：
- `std::filesystem::path`：表示文件路径，自动处理平台差异（Windows 反斜杠 vs Linux 正斜杠）；
- `std::filesystem::directory_iterator`：遍历目录条目；
- `std::filesystem::recursive_directory_iterator`：递归遍历子目录；
- `std::filesystem::file_status` / `status()`：查询文件类型、权限、修改时间等；
- `copy()`、`remove()`、`rename()`、`create_directory()` 等：文件操作。

```cpp
// filesystem_basic.cpp
#include <iostream>
#include <filesystem>
#include <fstream>

namespace fs = std::filesystem;

int main() {
    fs::path dir = "temp_demo_dir";
    fs::create_directories(dir);           // 递归创建目录

    fs::path file = dir / "hello.txt";     // / 运算符拼接路径，跨平台安全
    std::ofstream out(file);
    out << "Hello, filesystem!\n";

    std::cout << "文件存在吗？ " << fs::exists(file) << '\n';
    std::cout << "文件大小：" << fs::file_size(file) << " 字节\n";
    std::cout << "文件名：" << file.filename() << '\n';
    std::cout << "扩展名：" << file.extension() << '\n';

    fs::remove_all(dir);                   // 递归删除目录及内容
    std::cout << "删除后是否存在？ " << fs::exists(dir) << '\n';
}
```

`path` 使用 `/` 运算符拼接子路径，在 Windows 上会自动转成反斜杠，避免了手动字符串拼接路径的平台兼容性问题。

### 11.3.2 目录遍历

```cpp
// directory_iterate.cpp
#include <iostream>
#include <filesystem>

namespace fs = std::filesystem;

int main() {
    fs::path dir = ".";   // 当前目录

    std::cout << "当前目录下的条目：\n";
    for (const auto& entry : fs::directory_iterator(dir)) {
        std::cout << "  " << entry.path().filename();
        if (entry.is_directory()) {
            std::cout << " [目录]";
        } else if (entry.is_regular_file()) {
            std::cout << " [文件，" << fs::file_size(entry) << " 字节]";
        }
        std::cout << '\n';
    }
}
```

`directory_iterator` 只遍历一层；如果要递归遍历子目录，用 `recursive_directory_iterator`。遍历时可能抛出 `std::filesystem::filesystem_error`（如权限不足），建议包裹在 `try/catch` 里。

### 11.3.3 文件操作与错误处理重载

`<filesystem>` 的大部分操作提供两种重载：
1. **抛异常版本**：操作失败抛 `std::filesystem::filesystem_error`；
2. **错误码版本**：接受 `std::error_code& ec` 参数，失败时设置 `ec`，不抛异常。

```cpp
// filesystem_error_handling.cpp
#include <iostream>
#include <filesystem>
#include <system_error>

namespace fs = std::filesystem;

int main() {
    std::error_code ec;
    bool removed = fs::remove("不存在的文件.txt", ec);
    if (ec) {
        std::cerr << "删除失败：" << ec.message() << '\n';
    } else {
        std::cout << "删除成功，removed=" << removed << '\n';
    }
}
```

禁止异常的环境（如嵌入式内核、部分游戏引擎）优先使用错误码版本；日常应用开发用抛异常版本代码更简洁。

### 11.3.4 文件系统选型建议

| 需求 | 推荐设施 | 备注 |
|---|---|---|
| 跨平台路径拼接 | `std::filesystem::path` | 避免手动字符串拼接路径 |
| 遍历目录 | `directory_iterator` / `recursive_directory_iterator` | 注意权限异常 |
| 查询文件大小/类型/修改时间 | `fs::file_size()` / `fs::status()` | 返回 `file_status` |
| 复制/删除/重命名/创建目录 | `fs::copy` / `fs::remove` / `fs::rename` / `fs::create_directories` | 有抛异常和错误码两种重载 |
| 禁止异常环境 | 错误码重载 `ec` | 与 `std::error_code` 配合 |

> **反例**：不要用字符串拼接路径（如 `folder + "/" + filename`），在 Windows 上分隔符不同会出错；始终用 `fs::path` 和 `/` 运算符。

> **小结**：`iostream` 负责控制台流式输入输出，`std::osyncstream` 解决多线程输出交错；`stringstream` 适合内存中流式格式化，`spanstream`（C++23）适合无堆分配场景；`<filesystem>`（C++17）提供跨平台的路径、目录遍历和文件操作，优先用 `path` 而非手动拼接字符串。

## 本章小结

本章我们学习了标准库 I/O 与文件系统设施：

1. **`iostream`**：`cin/cout/cerr/clog` 进行标准输入输出，`<<`/`>>` 流式读写，`endl` 与 `'\n'` 的性能差异；
2. **流状态与错误**：`good()`/`fail()`/`eof()`/`bad()` 检查流状态，`clear()` + `ignore()` 恢复失败的输入流；
3. **格式化操纵符**：`<iomanip>` 的 `setw`/`setfill`/`fixed`/`setprecision` 等控制输出格式；
4. **`std::osyncstream`（C++20）**：多线程向同一流输出时防止交错；
5. **`std::stringstream`**：内存中的字符串流，适合字符串与数值互转；
6. **`std::spanstream`（C++23）**：基于固定缓冲区的无分配流，适合嵌入式和低延迟场景；
7. **`<filesystem>`（C++17）**：`path`、目录遍历、文件状态查询、复制/删除/重命名，跨平台安全。

选型口诀：**控制台打印用 `cout`，多线程输出用 `osyncstream`，内存中拼接字符串用 `stringstream` 或 `format`，无堆分配流用 `spanstream`，文件和目录操作用 `filesystem`。**

下一章（第 12 章）是全书唯一的并发专章，我们将学习线程生命周期、锁与条件变量、同步原语、原子与内存序、原子智能指针、危险指针/RCU 以及协程与异步执行。
