# 第 10 章 字符串、文本与正则库

文本处理是几乎每个程序都要面对的任务：读取用户输入、打印日志、解析配置文件、校验邮箱格式……本章我们学习标准库里与文本相关的核心设施：

- 10.1 `std::string`、`std::string_view` 与现代字符串操作；
- 10.2 格式化库：`std::format` 与 `std::print`；
- 10.3 字符分类、本地化与 Unicode 基础；
- 10.4 正则表达式库。

核心原则依然是**选型而非 API 罗列**：什么时候用 `string`、什么时候用 `string_view`、什么时候用 `format` 而不是 `cout <<`，每一节都会给出决策依据和反例。

> **工具约定**：示例以 C++20 为基线；使用 C++23 的 `std::print`/`std::println`、`resize_and_overwrite` 等时会标注编译器要求，并尽量提供 C++20 降级写法。代码片段可用 `cxxsh` 单文件验证，放入真实项目时请套用第 7.7 节的 CMake + vcpkg 工程模板。

## 10.1 `std::string`、`std::string_view` 与字符串操作

### 10.1.1 `std::string`：拥有字符数据的字符串

`std::string`（`<string>`）是标准库里最常用的字符串类型。它**拥有**字符数据，内部自动管理内存，你可以随意修改、拼接、截取，不用担心内存泄漏或悬空指针。

```cpp
// string_basic.cpp
#include <iostream>
#include <string>

int main() {
    std::string greeting = "你好";      // 拥有自己的内存
    greeting += ", 世界";               // 拼接，内部自动扩容
    greeting += "!";

    std::cout << greeting << '\n';
    std::cout << "长度：" << greeting.size() << '\n';
    std::cout << "第 1 个字符：" << greeting[0] << '\n';

    // 子串
    std::string part = greeting.substr(0, 2);
    std::cout << "子串：" << part << '\n';

    // 查找
    auto pos = greeting.find("世");
    if (pos != std::string::npos) {
        std::cout << "找到“世”在位置 " << pos << '\n';
    }
}
```

输出：

```
你好, 世界!
长度：9
第 1 个字符：你
子串：你好
找到“世”在位置 2
```

`std::string` 的常见操作：
- `+` / `+=`：拼接；
- `size()` / `length()`：字符个数（注意：对多字节字符如中文，这是字节数或字符数视编码而定，不是“显示宽度”）；
- `substr(pos, count)`：取子串；
- `find(sub)`：查找子串，找不到返回 `std::string::npos`；
- `compare`：比较两个字符串。

### 10.1.2 `std::string_view`：不拥有数据的轻量视图

C++17 引入了 `std::string_view`（`<string_view>`）。它是一个**非拥有的字符串视图**，内部只保存一个指针和一个长度，不复制也不拥有底局字符数据。它的设计目的是：当你只需要“读”一下一段字符，不想为临时观察付出内存拷贝代价时，用 `string_view` 代替 `const std::string&`。

```cpp
// string_view_basic.cpp
#include <iostream>
#include <string>
#include <string_view>

void print_length(std::string_view sv) {
    std::cout << "长度：" << sv.size() << ", 内容：" << sv << '\n';
}

int main() {
    std::string owned = "hello, world";
    std::string_view view = owned;   // 不拷贝，只是观察

    std::cout << view << '\n';

    print_length("字面量");          // 字符串字面量可隐式转为 string_view
    print_length(owned);             // string 也可隐式转
}
```

输出：

```
hello, world
长度：4，内容：字面量
长度：12，内容：hello, world
```

`string_view` 的关键特点：
- **零拷贝**：构造 `string_view` 不分配内存，不复制字符；
- **只读**：不能通过 `string_view` 修改底层字符；
- **不拥有生命周期**：你必须保证被观察的字符数据比 `string_view` 活得更久。

### 10.1.3 `string_view` 的致命陷阱：悬空视图

因为 `string_view` 不拥有数据，最容易犯的错误是让它指向一个已经销毁的临时对象：

```cpp
// 危险示例
std::string_view bad() {
    std::string temp = "临时字符串";
    return std::string_view(temp);  // temp 在函数返回时销毁，返回的视图悬空！
}
```

调用 `bad()` 并使用返回的 `string_view`，是未定义行为。

正确做法是：如果函数需要返回字符串，返回 `std::string`（拥有数据）；如果函数只需要观察调用方传进来的字符串，参数用 `std::string_view`，不要返回指向局部变量的视图。

**选型口诀**：
- 函数**参数**只读观察字符串 → `std::string_view`（避免拷贝）；
- 函数**返回值**需要字符串 → `std::string`（拥有数据）；
- 成员变量长期保存字符串 → `std::string`，不要用 `string_view`，除非你非常确定底层数据寿命足够长。

### 10.1.4 C++20/23 的新字符串操作

C++20 起，`std::string` 和 `std::string_view` 增加了一批实用成员：

```cpp
// string_modern_ops.cpp
#include <iostream>
#include <string>

int main() {
    std::string s = "hello, world";

    std::cout << std::boolalpha;
    std::cout << "以 hello 开头？ " << s.starts_with("hello") << '\n';   // C++20
    std::cout << "以 world 结尾？ " << s.ends_with("world") << '\n';    // C++20

    bool contains = s.contains(",");                                   // C++23
    std::cout << "包含逗号？ " << contains << '\n';
}
```

`starts_with`、`ends_with`（C++20）和 `contains`（C++23）让字符串判断更直观，不用再写 `find(...) == 0` 或 `find(...) != npos`。

`resize_and_overwrite`（C++23）允许在已知最终长度的情况下，一次性把 `string` 扩大并填充内容，避免反复拼接导致的多次扩容，适合性能敏感的字符串构造。

> **小结**：`std::string` 拥有数据，适合拥有和修改字符串；`std::string_view` 不拥有数据，适合只读函数参数，零拷贝；注意不要返回指向局部对象的 `string_view`；C++20/23 增加了 `starts_with`、`ends_with`、`contains` 等实用操作。

## 10.2 格式化库：`std::format` 与 `std::print`

### 10.2.1 为什么需要 `std::format`

传统的 C++ 字符串拼接有两种主流方式，各有缺陷：

1. **`std::cout <<` 流式拼接**：类型安全，但语法啰嗦，无法直接写格式模板（比如“%.2f”那种保留小数位的写法），国际化也不方便。
2. **C 风格 `sprintf` / `snprintf`**：格式字符串简洁，但类型不安全，传错参数类型是未定义行为，缓冲区溢出风险高。

C++20 引入了 **`std::format`**（`<format>`），结合两者的优点：
- 用 `{}` 占位符，类型安全，编译期可检查格式字符串；
- 支持自定义类型的格式化（通过特化 `std::formatter`）；
- 性能通常优于 `sprintf`，且无缓冲区溢出风险。

```cpp
// format_basic.cpp
// 需要 C++20 编译器和支持 <format> 的标准库（如 GCC 13+、MSVC 19.30+、libstdc++/libc++ 较新版本）
#include <iostream>
#include <format>
#include <string>
#include <chrono>

int main() {
    std::string name = "张三";
    int age = 25;
    double score = 89.567;

    std::string s = std::format("姓名：{}，年龄：{}，成绩：{:.2f}", name, age, score);
    std::cout << s << '\n';

    // 自定义类型格式化示例（std::chrono 的 duration 已内置支持）
    auto now = std::chrono::system_clock::now();
    std::cout << std::format("当前时间：{:%Y-%m-%d %H:%M:%S}\n", now);
}
```

可能的输出：

```
姓名：张三，年龄：25，成绩：89.57
当前时间：2026-11-11 09:12:04
```

`std::format` 返回一个 `std::string`。如果你不需要字符串对象，只想直接打印到控制台，C++23 提供了 `std::print` / `std::println`。

### 10.2.2 `std::print` 与 `std::println`（C++23）

`std::print`（`<print>`）直接把格式化后的内容写到输出流（默认标准输出），避免先构造 `std::string` 再写流的中间开销；`std::println` 会自动追加换行。

```cpp
// print_basic.cpp
// 需要 C++23 编译器和标准库支持（如 MSVC 19.40+、GCC 14.2+ 等）
#include <iostream>
#include <print>

int main() {
    std::print("Hello, {}\n", "world");     // 手动换行
    std::println("Hello, {}", "world");     // 自动换行
}
```

输出：

```
Hello, world
Hello, world
```

### 10.2.3 自定义类型的格式化：特化 `std::formatter`

如果你想让自定义类型也能用 `{}` 格式化，需要特化 `std::formatter<T>`，实现 `parse` 和 `format` 两个成员函数。下面是一个最小示例：

```cpp
// format_custom.cpp
#include <iostream>
#include <format>
#include <string>

struct Point {
    int x;
    int y;
};

template <>
struct std::formatter<Point> {
    // 解析格式字符串（这里简单处理，不支持自定义格式）
    constexpr auto parse(std::format_parse_context& ctx) {
        return ctx.begin();
    }

    // 格式化输出
    auto format(const Point& p, std::format_context& ctx) const {
        return std::format_to(ctx.out(), "({},{})", p.x, p.y);
    }
};

int main() {
    Point p{3, 4};
    std::cout << std::format("点坐标：{}\n", p);   // 点坐标：(3,4)
}
```

自定义格式化是进阶内容，初学者只需要知道“可以让自己的类型支持 `{}` 格式化”即可，具体实现可在第 5 章模板基础扎实后再深入。

### 10.2.4 `format` / `print` vs `cout <<`：怎么选

| 场景 | 推荐方式 | 原因 |
|---|---|---|
| 快速调试输出、不需要格式控制 | `std::cout <<` | 最简单，无需额外头文件 |
| 构造格式化字符串（日志、报表、UI 文本） | `std::format` | 模板清晰、类型安全、可复用 |
| 直接打印到控制台，不需要中间字符串 | `std::print` / `std::println`（C++23） | 零中间字符串，代码更简洁 |
| 需要 C 风格 `printf` 兼容 | `std::snprintf` | 旧代码互操作，但类型不安全 |

**反例**：不要为了格式化一个简单的字符串而大量写 `std::cout << a << " " << b << " " << c`，既啰嗦又难调整格式；也不要为了性能在热点代码里反复调用 `std::format` 构造临时 `std::string`，如果只需要打印，用 `std::print`。

> **注意**：`std::format` 是 C++20，`std::print`/`std::println` 是 C++23。旧编译器可以用 `fmt` 库（`std::format` 的前身，API 几乎一样）作为过渡，或者继续用 `std::cout <<`。

## 10.3 字符分类、本地化与 Unicode 基础

### 10.3.1 字符分类：`<cctype>` 与 `<locale>`

C++ 继承了 C 语言的 `<cctype>` 字符分类函数，如 `std::isdigit`、`std::isalpha`、`std::isspace`、`std::tolower`、`std::toupper` 等。这些函数作用于单个字符（`char` 或 `unsigned char`），判断它是不是数字、字母、空白符等。

```cpp
// ctype_basic.cpp
#include <iostream>
#include <cctype>
#include <string>

int main() {
    std::string s = "Hello 2026!";
    int digits = 0, letters = 0;

    for (unsigned char c : s) {   // 注意：传入 unsigned char 避免未定义行为
        if (std::isdigit(c)) ++digits;
        if (std::isalpha(c)) ++letters;
    }

    std::cout << "数字个数：" << digits << ", 字母个数：" << letters << '\n';
}
```

输出：

```
数字个数：4, 字母个数：5
```

**避坑**：`<cctype>` 的函数期望参数能转换为 `unsigned char` 或 `EOF`。直接传 `char`（如果 `char` 是有符号的）且字符是非 ASCII（负值），可能导致未定义行为。最佳实践是显式转成 `unsigned char` 再传。

`<locale>` 提供了更强大的本地化支持（如按特定语言规则排序、货币格式、数字分组等），但 API 复杂，初学者遇到具体本地化需求时再查阅。

### 10.3.2 Unicode 基础与字符类型

C++ 内置的字符类型包括：
- `char`：窄字符，通常用于 UTF-8 或系统默认编码；
- `wchar_t`：宽字符，大小随平台而定（Windows 通常 2 字节，Linux 通常 4 字节）；
- `char16_t` / `char32_t`：C++11 起，分别用于 UTF-16 和 UTF-32。

字符串字面量前缀：
- `"hello"`：`const char[]`，通常是 UTF-8（取决于编译器和源文件编码）；
- `L"hello"`：`const wchar_t[]`；
- `u"hello"`：`const char16_t[]`，通常 UTF-16；
- `U"hello"`：`const char32_t[]`，通常 UTF-32；
- `u8"hello"`：C++20 起，明确 `const char8_t[]`，UTF-8。

标准库的 `std::string`、`std::wstring`、`std::u16string`、`std::u32string` 分别对应这些字符类型。

**初学者需要明白**：`std::string` 本身不关心编码，它只是一串字节。如果里面存的是 UTF-8 编码的中文，`size()` 返回的是**字节数**，而不是“字符个数”或“显示宽度”。想正确处理 Unicode 文本（如按字符数截取、计算显示列宽），通常需要第三方库（如 ICU、UTF8-CPP），标准库本身不提供完整的 Unicode 处理能力。

C++23 增加了文本编码相关的查询设施（如 `std::text_encoding` 相关提案，支持情况有限），初学者只需要知道“字节 ≠ 字符”这个基本概念即可。

## 10.4 正则表达式库

### 10.4.1 `<regex>` 基本用法

C++11 引入了 `<regex>`，提供 ECMAScript 语法的正则表达式支持。核心组件包括：
- `std::regex`：编译后的正则模式；
- `std::smatch` / `std::cmatch`：匹配结果；
- `std::regex_match`：整个字符串必须匹配；
- `std::regex_search`：字符串中搜索匹配；
- `std::regex_replace`：替换匹配部分。

```cpp
// regex_basic.cpp
#include <iostream>
#include <regex>
#include <string>

int main() {
    std::string text = "我的电话是 138-0000-0000，另一个是 139-1111-2222";

    // 手机号正则：3位区段 - 4位区段 - 4位区段
    std::regex phone_regex(R"(\d{3}-\d{4}-\d{4})");

    // 搜索第一个匹配
    std::smatch m;
    if (std::regex_search(text, m, phone_regex)) {
        std::cout << "找到电话：" << m.str() << '\n';
    }

    // 替换所有电话号码
    std::string result = std::regex_replace(text, phone_regex, "[隐藏]");
    std::cout << result << '\n';
}
```

输出：

```
找到电话：138-0000-0000
我的电话是 [隐藏]，另一个是 [隐藏]
```

原始字符串字面量 `R"(...)"` 很适合写正则，因为里面不需要转义反斜杠。

### 10.4.2 正则的性能代价

正则表达式使用起来方便，但有明显的性能代价：
1. **编译代价**：`std::regex` 对象的构造涉及状态机编译，相对昂贵。如果同一个正则要用很多次，应该把 `std::regex` 对象缓存起来，不要在循环里反复构造。
2. **匹配代价**：复杂的正则（特别是有大量回溯的模式）在长字符串上可能很慢。

**反例**：不要在循环里每次迭代都构造一个 `std::regex`；也不要用正则去做简单的子串查找（`string::find` 更快、更简单）。

```cpp
// 推荐：缓存正则对象
std::regex phone_regex(R"(\d{3}-\d{4}-\d{4})");  // 在函数外或静态局部变量中定义一次
for (const auto& line : lines) {
    std::regex_search(line, m, phone_regex);   // 反复使用同一个 regex 对象
}
```

### 10.4.3 正则选型建议

| 任务 | 推荐工具 | 原因 |
|---|---|---|
| 简单子串查找 | `std::string::find` | 最快，无需正则开销 |
| 字符串分割 | 手动循环或 `std::string_view` + `find` | 正则分割在 C++ 标准库里不够方便 |
| 复杂模式匹配（邮箱、URL、日志解析） | `std::regex` | 表达能力强，代码简洁 |
| 高频调用的正则 | 缓存 `std::regex` 对象 | 避免重复编译开销 |
| 极高性能文本处理 | 第三方库（如 RE2、对象池 + 自有解析） | `std::regex` 实现质量随编译器而异 |

> **小结**：正则适合复杂模式匹配，但要注意编译和匹配的性能代价，缓存 `std::regex` 对象，简单查找优先用 `string::find`。

## 本章小结

本章我们学习了标准库字符串、文本与正则设施：

1. **`std::string`**：拥有字符数据，适合拥有和修改字符串；
2. **`std::string_view`**：非拥有的轻量视图，适合只读函数参数，零拷贝；注意不要返回指向局部对象的视图；
3. **`std::format`（C++20）**：类型安全的格式化，用 `{}` 占位符，可特化 `std::formatter` 支持自定义类型；
4. **`std::print`/`std::println`（C++23）**：直接打印格式化内容，无需中间字符串；
5. **字符分类与 Unicode**：`<cctype>` 做基础字符分类，注意传 `unsigned char`；`std::string` 本身不关心编码，字节 ≠ 字符；
6. **正则表达式**：`<regex>` 支持 ECMAScript 语法，适合复杂模式匹配，注意缓存 `std::regex` 对象、简单查找用 `find`。

选型口诀：**只读观察用 `string_view`，拥有修改用 `string`；格式化输出用 `format`/`print`；复杂模式匹配用正则，简单查找用 `find`。**
