# 第 25 章 Boost 并发与网络

在标准库 `<thread>`、`<mutex>`、`<atomic>` 普及之前，Boost 已经提供了成熟的并发和网络设施。即使在 C++20/23 之后，Boost 在这些领域仍有不可替代的优势：Boost.Asio 的异步 I/O 模型是工业级网络编程的事实标准，Boost.Fiber 提供了用户态协程，Boost.Thread 在旧代码库中仍被大量使用。

本章覆盖：

- 25.1 `boost::asio`：异步 I/O 与网络编程的统一模型；
- 25.2 `boost::thread` 与同步设施的“前标准时代”价值；
- 25.3 `boost::coroutine2`、`boost::fibers` 与 C++20 协程的对比。

每一节都会标注该设施的定位：**已被标准化 / 部分标准化 / 纯 Boost 独有**。

> **工具约定**：示例默认采用 CMake + vcpkg 工程模板，Boost 依赖通过 vcpkg 清单引入。Boost.Asio 及相关库大多是 header-only，但 `boost::asio` 的部分后端（如 `boost::asio::serial_port`）可能需要链接 `boost::system`。代码片段可用 `cxxsh` 单文件验证（需链接对应 compiled Boost 库时按平台添加库路径），放入真实项目时请套用第 7.7 节的工程模板。

## 25.1 `boost::asio`：异步 I/O 与网络编程的统一模型

### 25.1.1 什么是 Boost.Asio

Boost.Asio（异步 I/O 输入输出）是 Boost 中最著名、使用最广泛的库之一，提供跨平台的异步网络和 I/O 功能。它覆盖 TCP、UDP、Unix 域套接字、定时器、串口等，核心设计围绕：

- `io_context`：I/O 服务对象，管理所有异步操作的调度；
- 异步操作与完成处理器（completion handler）：发起异步操作后立即返回，操作完成时回调处理器；
- `strand`：确保特定处理器在同一线程中串行执行，避免手动加锁；
- C++20 起，还提供 `co_spawn` 和 `awaitable`，与标准协程衔接。

定位：**纯 Boost 独有**（标准库目前没有成熟的异步网络 I/O 库，C++23/26 的 `std::execution` 仍在标准化中，尚未覆盖 Asio 的完整能力）。

### 25.1.2 核心概念：io_context 与异步操作

`boost::asio::io_context` 是 Asio 程序的核心。所有异步操作都绑定到一个 `io_context`，程序通过 `io_context.run()` 进入事件循环，Asio 负责调度和触发完成处理器。

下面是一个最小的异步定时器示例：

```cpp
// asio_timer_basic.cpp
// Boost.Asio 是 header-only，但通常需要链接 boost::system
#include <iostream>
#include <boost/asio.hpp>

int main() {
    boost::asio::io_context io;

    // 创建一个 1 秒后超时的定时器
    boost::asio::steady_timer timer(io, boost::asio::chrono::seconds(1));

    // 异步等待，超时时调用 lambda
    timer.async_wait([](const boost::system::error_code& ec) {
        if (!ec) {
            std::cout << "定时器超时，1 秒到了\n";
        }
    });

    // 进入事件循环，处理异步操作
    io.run();

    std::cout << "io_context 运行结束\n";
}
```

输出：

```
定时器超时，1 秒到了
io_context 运行结束
```

关键点：
- `timer.async_wait(handler)` 立即返回，不会阻塞主线程；
- `io.run()` 阻塞直到所有异步操作完成且没有更多工作；
- 完成处理器接收一个 `boost::system::error_code` 参数，表示操作是否成功。

### 25.1.3 TCP 服务器与客户端（简化示例）

Asio 最强大的地方是异步网络编程。下面是一个极简的 TCP “回音”服务器骨架，展示接受连接和异步读写的模式：

```cpp
// asio_tcp_echo_basic.cpp
// 需要链接 boost::system（及可能的 boost::thread，视平台而定）
#include <iostream>
#include <boost/asio.hpp>

using boost::asio::ip::tcp;

void session(tcp::socket socket, boost::asio::io_context& io) {
    auto self = std::make_shared<tcp::socket>(std::move(socket));
    std::array<char, 1024> buffer;

    // 异步读取
    self->async_read_some(boost::asio::buffer(buffer),
        [self, &buffer](const boost::system::error_code& ec, std::size_t bytes_transferred) {
            if (!ec) {
                // 原样写回（回音）
                boost::asio::async_write(*self, boost::asio::buffer(buffer, bytes_transferred),
                    [self](const boost::system::error_code& ec, std::size_t /*n*/) {
                        if (!ec) {
                            // 可继续读取下一条
                        }
                    });
            }
        });
}

int main() {
    try {
        boost::asio::io_context io;

        tcp::acceptor acceptor(io, tcp::endpoint(tcp::v4(), 8080));

        acceptor.async_accept([&acceptor, &io](const boost::system::error_code& ec, tcp::socket socket) {
            if (!ec) {
                session(std::move(socket), io);
                // 接受下一个连接
                acceptor.async_accept([&acceptor, &io](const boost::system::error_code& ec2, tcp::socket socket2) {
                    if (!ec2) {
                        session(std::move(socket2), io);
                    }
                });
            }
        });

        io.run();
    } catch (const std::exception& e) {
        std::cerr << "异常：" << e.what() << '\n';
    }
}
```

这个示例展示了 Asio 的典型风格：每个异步操作都接受一个 lambda 作为完成处理器，操作完成后在 `io_context` 的事件循环里被调用。实际生产代码中，通常会用 `boost::asio::co_spawn` 配合 C++20 协程，把回调式代码写成更线性的协程形式（见下文）。

### 25.1.4 `strand`：串行化回调执行

在多线程环境下运行一个 `io_context` 时，多个线程可能同时调用 `io.run()`，完成处理器可能在不同线程上执行。如果多个处理器访问共享数据，就需要同步。

`boost::asio::strand` 提供了一种轻量级的串行化机制：绑定到同一个 `strand` 的处理器保证**在同一线程中串行执行**，不需要用户手动加锁。

```cpp
// asio_strand_basic.cpp
#include <iostream>
#include <boost/asio.hpp>

int main() {
    boost::asio::io_context io;
    boost::asio::strand<boost::asio::io_context::executor_type> strand(io.get_executor());

    // 两个异步操作绑定到同一个 strand，它们的处理器保证串行
    boost::asio::post(boost::asio::bind_executor(strand, [] {
        std::cout << "处理器 A\n";
    }));
    boost::asio::post(boost::asio::bind_executor(strand, [] {
        std::cout << "处理器 B\n";
    }));

    io.run();
}
```

输出：

```
处理器 A
处理器 B
```

### 25.1.5 C++20 协程衔接：`co_spawn` 与 `awaitable`

Boost.Asio 在 C++20 后支持标准协程：`boost::asio::co_spawn` 可以启动一个协程，`co_await` 可以等待 Asio 的异步操作，把回调式代码写成线性风格。

```cpp
// asio_coroutine_basic.cpp
// 需要 C++20 编译器和 Boost.Asio 支持 co_spawn
#include <iostream>
#include <boost/asio.hpp>
#include <boost/asio/co_spawn.hpp>
#include <boost/asio/steady_timer.hpp>
#include <boost/asio/use_awaitable.hpp>

namespace asio = boost::asio;
using asio::awaitable;
using asio::co_spawn;
using asio::steady_timer;
using asio::use_awaitable;

awaitable<void> timer_coro(asio::any_io_exec ex) {
    steady_timer timer(ex, asio::chrono::seconds(1));
    co_await timer.async_wait(use_awaitable);
    std::cout << "协程里的定时器超时\n";
}

int main() {
    asio::io_context io;
    co_spawn(io, timer_coro(io.get_executor()), asio::detached);
    io.run();
}
```

`co_await timer.async_wait(use_awaitable)` 会挂起协程，等定时器超时后恢复，无需写回调 lambda。代码读起来像同步代码，实际仍是异步非阻塞。

### 25.1.6 选型建议

| 需求 | 推荐 | 原因 |
|---|---|---|
| 跨平台异步 TCP/UDP 服务器、客户端 | `boost::asio` | 工业级、成熟、文档丰富，标准库无对应 |
| 定时器、异步文件 I/O、串口 | `boost::asio` | 统一模型，和网络 I/O 共用 `io_context` |
| 多线程共享 `io_context`，需串行回调 | `boost::asio::strand` | 避免手动锁，轻量串行化 |
| 回调嵌套太深（“回调地狱”） | `co_spawn` + `awaitable`（C++20）| 把异步流程写成线性协程 |

## 25.2 `boost::thread` 与同步设施的“前标准时代”价值

### 25.2.1 Boost.Thread 的历史地位

在 C++11 之前，C++ 标准库没有线程库。Boost.Thread（`boost::thread`、`boost::mutex`、`boost::condition_variable` 等）是那个时代最成熟的跨平台多线程库，C++11 的 `std::thread` 很大程度上参考了 Boost.Thread 的设计。

定位：**已被标准化**（C++11 `std::thread`、`std::mutex`、`std::condition_variable` 等基本对应）。新代码优先用标准库，`boost::thread` 主要用于维护旧代码库或需要标准库尚未提供的特性（如 `boost::thread` 的某些扩展属性）。

### 25.2.2 Boost.Thread 与 std::thread 的对照

| Boost.Thread | 标准库对应 | 备注 |
|---|---|---|
| `boost::thread` | `std::thread` | 基本一致 |
| `boost::mutex` / `boost::recursive_mutex` | `std::mutex` / `std::recursive_mutex` | 基本一致 |
| `boost::condition_variable` | `std::condition_variable` | 基本一致 |
| `boost::lock_guard` / `boost::unique_lock` | `std::lock_guard` / `std::unique_lock` | 基本一致 |
| `boost::this_thread::sleep_for` | `std::this_thread::sleep_for` | 基本一致 |

旧代码中大量使用 `boost::thread` 时，维护时保持不变即可；新代码中除非有特殊原因，否则应直接用 `std::thread` 等标准设施，减少对 Boost 的依赖。

### 25.2.3 何时仍可能用 Boost.Thread

- 项目仍在用 C++98/03，无法升级到 C++11；
- 需要 Boost.Thread 提供但标准库没有的扩展（如特定的线程属性、命名、优先级控制等，视平台而定）；
- 与已大量使用 Boost.Asio 的代码集成，且希望线程命名/管理与 Asio 的 `io_context` 线程池统一。

> **小结**：`boost::thread` 是标准线程库的前身，新代码优先 `std::thread`；Boost.Thread 的价值主要在于维护旧代码和极少数标准库未覆盖的线程扩展。

## 25.3 `boost::coroutine2`、`boost::fibers` 与 C++20 协程的对比

### 25.3.1 两种协程模型

C++ 世界里有两种协程：

1. **无栈协程（stackless coroutine）**：C++20 标准协程（`co_await`/`co_yield`/`co_return`），挂起时只保存局部变量和执行点，栈帧不完整保存，挂起点必须在协程自身的函数体内（不能跨函数挂起）；
2. **栈式协程（stackful coroutine）**：`boost::coroutine2` 提供的协程，挂起时保存完整的栈，可以跨函数挂起，类似于有自己栈的轻量级线程。

Boost.Fiber（`boost::fibers`）是在栈式协程基础上构建的用户态调度器，提供类似线程的 API（`fiber` 对象、`join`、`yield` 等），但由用户态库调度，不涉及内核线程切换。

定位：**纯 Boost 独有**（标准库只有 C++20 无栈协程，没有栈式协程和用户态纤程标准化）。

### 25.3.2 `boost::coroutine2` 基本用法

```cpp
// boost_coroutine2_basic.cpp
// 需要链接 boost::context（compiled 库）
#include <iostream>
#include <boost/coroutine2/all.hpp>

using namespace boost::coroutines2;

int main() {
    // coroutine<void()> 是一个无参数、无返回值的协程
    coroutine<void()>::push_type sink([&](coroutine<void()>::pull_type& source) {
        std::cout << "协程开始\n";
        source();   // 挂起，回到 main
        std::cout << "协程恢复\n";
        source();   // 再次挂起
        std::cout << "协程结束\n";
    });

    std::cout << "main: 第一次 resume\n";
    sink();
    std::cout << "main: 第二次 resume\n";
    sink();
    std::cout << "main: 结束\n";
}
```

输出：

```
main: 第一次 resume
协程开始
main: 第二次 resume
协程恢复
main: 结束
协程结束
```

### 25.3.3 `boost::fibers`：用户态纤程

`boost::fiber` 提供了类似 `std::thread` 的 API，但调度在用户态进行：

```cpp
// boost_fiber_basic.cpp
// 需要链接 boost::fiber 和 boost::context
#include <iostream>
#include <boost/fiber/all.hpp>

int main() {
    boost::fibers::fiber f1([] {
        std::cout << "纤程 1 开始\n";
        boost::this_fiber::yield();  // 主动让出 CPU
        std::cout << "纤程 1 恢复\n";
    });

    boost::fibers::fiber f2([] {
        std::cout << "纤程 2 开始\n";
        boost::this_fiber::yield();
        std::cout << "纤程 2 恢复\n";
    });

    f1.join();
    f2.join();
    std::cout << "所有纤程结束\n";
}
```

可能的输出：

```
纤程 1 开始
纤程 2 开始
纤程 1 恢复
纤程 2 恢复
所有纤程结束
```

### 25.3.3 三种协程/纤程对比

| 维度 | C++20 无栈协程 | Boost.Coroutine2（栈式协程） | Boost.Fiber（用户态纤程） |
|---|---|---|---|
| 栈保存 | 仅协程帧，不保存完整栈 | 完整栈，可跨函数挂起 | 完整栈 |
| 挂起点限制 | 必须在协程自身函数体 | 可在任意嵌套函数中挂起 | 可在任意嵌套函数中挂起 |
| 调度 | 编译器+运行时辅助，用户显式 co_await | 用户显式 `source()` / `sink()` | 用户态调度器，类似线程 |
| 标准化 | C++20 标准 | 纯 Boost | 纯 Boost |
| 性能 | 极高，零开销上下文切换 | 高，有栈切换开销 | 高，用户态调度 |

选型建议：
- 新代码中需要异步/惰性序列，优先 C++20 `co_await`/`co_yield` + `std::generator`；
- 需要“跨函数挂起”或把现有同步代码改成协程式而不改函数签名，可考虑 Boost.Coroutine2；
- 需要大量轻量级并发任务且希望用类线程 API 调度，可考虑 Boost.Fiber；
- 以上均属“纯 Boost 独有”，引入前应评估是否真的需要栈式协程能力。

## 本章小结

本章我们学习了 Boost 并发与网络设施：

1. **`boost::asio`**：纯 Boost 独有，工业级异步 I/O 和网络库；`io_context` 事件循环、`async_*` 异步操作、`strand` 串行化、`co_spawn`/`awaitable` 与 C++20 协程衔接；
2. **`boost::thread`**：已被标准化，新代码优先 `std::thread`，主要用于维护旧代码；
3. **`boost::coroutine2`**：纯 Boost 独有，栈式协程，可跨函数挂起；
4. **`boost::fibers`**：纯 Boost 独有，用户态纤程，提供类线程 API 的用户态调度。

选型口诀：**异步网络 I/O 用 `boost::asio`；新代码多线程用 `std::thread`；需要跨函数挂起的协程用 `boost::coroutine2`；大量轻量用户态并发任务用 `boost::fibers`。**

下一章（第 26 章）我们进入 Boost 通用工具与函数式设施，学习 `boost::function`、`boost::bind`、`boost::signals2`、`boost::lexical_cast`、`boost::property_map`、`boost::dynamic_bitset`。
