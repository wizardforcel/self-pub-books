# 第 13 章 语言支持库

前面的章节讲了 C++ 的语言特性和常用标准库，但标准库还有一大批“后台支撑”设施，它们不直接完成业务逻辑，却为其他库和语言本身提供基础。比如：如何知道 `int` 能表示的最大值是多少？如何在运行期判断两个对象是不是同一种类型？如何在编译期检测编译器是否支持某个新特性？

本章（第三篇“标准库底层支撑与计算专项”的开篇）覆盖语言支持库：

- 13.1 类型属性、固定宽度整数与浮点限制：`std::numeric_limits`、`<cstdint>`、固定宽度浮点类型（C++23）、`<climits>`/`<cfloat>`；
- 13.2 `std::initializer_list`、`std::type_info` 与 `std::type_index`；
- 13.3 实现属性查询与特性测试宏：`__has_include`、`__cpp_lib_*`、`__cpp_*`。

> **工具约定**：示例以 C++20 为基线；涉及 C++23 的内容（如固定宽度浮点类型 `std::float32_t`）会标注编译器要求。代码片段可用 `cxxsh` 单文件验证，放入真实项目时请套用第 7.7 节的 CMake + vcpkg 工程模板。

## 13.1 类型属性、固定宽度整数与浮点限制

### 13.1.1 `std::numeric_limits`：问类型“极限是多少”

每种内置类型都能表示的值有一个范围，比如 `int` 通常能表示 -21 亿多到 21 亿多，`double` 能表示非常大或非常小的小数。如果你硬要把一个更大的数存进 `int`，就会发生溢出，结果是未定义行为。

为了不在代码里硬编码这些“极限值”（比如写 `2147483647` 这种魔法数字），C++ 提供了 `std::numeric_limits<T>`（`<limits>`），一个类模板，可以查询任意类型的极限属性。

```cpp
// numeric_limits_basic.cpp
#include <iostream>
#include <limits>

int main() {
    std::cout << "int 最大值： " << std::numeric_limits<int>::max() << '\n';
    std::cout << "int 最小值： " << std::numeric_limits<int>::min() << '\n';
    std::cout << "int 是否有符号： " << std::numeric_limits<int>::is_signed << '\n';
    std::cout << "int 数字位数： " << std::numeric_limits<int>::digits << '\n';
    std::cout << "int 是否为整数类型： " << std::numeric_limits<int>::is_integer << '\n';
    std::cout << "double 最大值： " << std::numeric_limits<double>::max() << '\n';
    std::cout << "double 最小正数： " << std::numeric_limits<double>::min() << '\n';
    std::cout << "double 精度（十进制位数）： " << std::numeric_limits<double>::digits10 << '\n';
    std::cout << "double 是否有无穷大： " << std::numeric_limits<double>::has_infinity << '\n';
}
```

可能的输出：

```
int 最大值： 2147483647
int 最小值： -2147483648
int 是否有符号： 1
int 数字位数： 31
int 是否为整数类型： 1
double 最大值： 1.79769e+308
double 最小正数： 2.22507e-308
double 精度（十进制位数）： 15
double 是否有无穷大： 1
```

`numeric_limits` 的所有成员都是 `static constexpr`，可以在编译期使用，比如用来定义数组大小或 `static_assert`：

```cpp
static_assert(std::numeric_limits<int>::max() > 100000, "int 范围太小了");
```

### 13.1.2 固定宽度整数类型：`<cstdint>`

`int`、`long` 等类型的大小在标准里只有“至少多少位”的保证，不同平台可能不同。比如 `long` 在 Windows 64 位上是 4 字节，在 Linux 64 位上通常是 8 字节。如果你需要确保某个整数**恰好是 32 位**或**恰好是 64 位**（比如做网络协议、文件格式、跨平台二进制交换），就应该用 `<cstdint>` 里的固定宽度整数类型。

| 类型 | 含义 | 头文件 |
|---|---|---|
| `std::int8_t` / `std::uint8_t` | 恰好 8 位，有符号/无符号 | `<cstdint>` |
| `std::int16_t` / `std::uint16_t` | 恰好 16 位 | `<cstdint>` |
| `std::int32_t` / `std::uint32_t` | 恰好 32 位 | `<cstdint>` |
| `std::int64_t` / `std::uint64_t` | 恰好 64 位 | `<cstdint>` |
| `std::intptr_t` / `std::uintptr_t` | 能存指针的有符号/无符号整数 | `<cstdint>` |

```cpp
// fixed_width_integers.cpp
#include <iostream>
#include <cstdint>

int main() {
    std::int32_t a = 100000;      // 恰好 32 位有符号
    std::uint64_t b = 10000000000ULL;  // 恰好 64 位无符号

    std::cout << "a = " << a << ", sizeof(a) = " << sizeof(a) << '\n';
    std::cout << "b = " << b << ", sizeof(b) = " << sizeof(b) << '\n';
}
```

**选型建议**：日常业务代码里，优先用 `int`、`double` 等原生类型，不要为了“固定宽度”而到处用 `int32_t`，除非你真的关心二进制布局（如网络协议、文件头、硬件寄存器）。

### 13.1.3 固定宽度浮点类型：C++23 前瞻

与整数类似，C++23 引入了固定宽度浮点类型，定义在 `<stdint.h>` 的 C++ 对应头文件 `<cstdint>` 里（部分实现也可能在 `<stdfloat>` 中，具体取决于标准库版本）：

- `std::float32_t`：32 位浮点（通常对应 `float`）；
- `std::float64_t`：64 位浮点（通常对应 `double`）；
- `std::float128_t`：128 位浮点（如果平台支持）。

这些类型是 C++23 的新内容，编译器支持情况有限，属于**前瞻特性**。如果你需要明确的浮点宽度，目前更稳妥的做法是用 `static_assert` 检查 `sizeof(float) == 4` 等假设，而不是直接依赖 `float32_t`。

```cpp
// fixed_width_float_check.cpp
#include <iostream>
#include <cstdint>

int main() {
    static_assert(sizeof(float) == 4, "本平台 float 不是 32 位");
    static_assert(sizeof(double) == 8, "本平台 double 不是 64 位");

    std::cout << "float 宽度假设成立\n";
}
```

### 13.1.4 `<climits>` 与 `<cfloat>`：C 语言风格的极限宏

除了 `std::numeric_limits`，C++ 还继承了 C 语言的 `<climits>` 和 `<cfloat>` 头文件，里面是一堆宏，比如：

- `INT_MAX`、`INT_MIN`：`int` 的最大/最小值；
- `CHAR_BIT`：一个字节的位数（通常是 8）；
- `FLT_MAX`、`DBL_MAX`：`float`/`double` 的最大值；
- `DBL_DIG`：`double` 的十进制精度。

这些宏是 C 风格的，不是类型安全的，且不受命名空间保护。现代 C++ 代码中，**优先用 `std::numeric_limits`**，只有在需要和 C 代码互操作、或者某些极限值 `numeric_limits` 没有直接提供时，才考虑 `<climits>`/`<cfloat>`。

> **小结**：`std::numeric_limits<T>` 是类型安全、可在编译期使用的极限查询工具；`<cstdint>` 提供固定宽度整数，适合二进制交换场景；C++23 的固定宽度浮点类型仍属前瞻；`<climits>`/`<cfloat>` 是 C 遗留宏，现代代码中优先 `numeric_limits`。

## 13.2 `std::initializer_list`、`std::type_info` 与 `std::type_index`

### 13.2.1 `std::initializer_list`：花括号初始化的底层载体

第 2 章讲过列表初始化 `{1, 2, 3}`。当你写 `std::vector<int> v = {1, 2, 3};` 时，编译器幕后用的正是 `std::initializer_list<int>`（`<initializer_list>`）。

`std::initializer_list<T>` 是一个轻量级的代理对象，内部只持有指向数组的指针和长度，**不拥有**那些元素。它的元素是 const 的，只能读不能改。它常用作构造函数参数，让类支持花括号初始化：

```cpp
// initializer_list_basic.cpp
#include <iostream>
#include <initializer_list>
#include <string>

class Bag {
public:
    Bag(std::initializer_list<int> list) {
        std::cout << "Bag 构造，元素个数：" << list.size() << '\n';
        for (int x : list) {
            std::cout << x << ' ';
        }
        std::cout << '\n';
    }
};

int main() {
    Bag b1{1, 2, 3, 4, 5};   // 构造函数接收 initializer_list<int>
    Bag b2{10, 20};          // 同上
}
```

输出：

```
Bag 构造，元素个数：5
1 2 3 4 5 
Bag 构造，元素个数：2
10 20 
```

注意第 2 章提到的一个优先级规则：如果一个类同时有接受 `std::initializer_list` 的构造函数和其他构造函数，花括号初始化会**优先匹配 `initializer_list` 构造函数**。这有时会导出违反直觉的结果，使用时要留意。

`std::initializer_list` 本身不能修改元素，且遍历只能单向进行（提供 `begin()`/`end()`）。如果你需要一个可修改、可扩容的序列，应用 `std::vector` 或其他容器，而不是 `initializer_list`。

### 13.2.2 `std::type_info`：运行期类型信息（RTTI）

C++ 是静态类型语言，编译期就知道每个变量的类型。但有些场景下，程序需要知道“对象在运行期的实际类型”，比如通过基类指针访问派生类对象时，想知道它到底是哪个派生类。这就是 **RTTI（Run-Time Type Information，运行期类型信息）**。

`std::type_info`（`<typeinfo>`）是 RTTI 的核心类。通过 `typeid` 运算符可以获取一个表达式的 `std::type_info` 引用：

```cpp
// type_info_basic.cpp
#include <iostream>
#include <typeinfo>
#include <string>

class Base {
public:
    virtual ~Base() = default;   // 必须有虚函数，typeid 才能进行多态查询
};

class Derived : public Base {};

int main() {
    Base b;
    Derived d;

    Base* pb = &d;   // 基类指针指向派生类对象

    std::cout << "b 的类型： " << typeid(b).name() << '\n';
    std::cout << "d 的类型： " << typeid(d).name() << '\n';
    std::cout << "pb 静态类型： " << typeid(pb).name() << '\n';      // 指针本身是 Base*
    std::cout << "pb 动态类型： " << typeid(*pb).name() << '\n';    // 解引用后是 Derived（多态查询）
}
```

可能的输出（不同编译器 `name()` 返回的字符串格式不同，可能是修饰名）：

```
b 的类型： 4Base
d 的类型： 7Derived
pb 静态类型： P4Base
pb 动态类型： 7Derived
```

关键点：
- `typeid(x).name()` 返回类型名字符串，但格式由编译器决定，不可移植，只适合调试打印，不适合做逻辑判断；
- 对带多态（有虚函数）的类型解引用后用 `typeid`，会得到**动态类型**（运行期的实际类型）；
- `typeid` 不能用于数组、void、未完全定义的类等。

`std::type_info` 的常用成员：
- `operator==` / `operator!=`：比较两个类型是否相同；
- `before(const std::type_info&)`：定义一种任意但确定的类型排序（用于把类型作为容器键）；
- `name()`：返回类型名字符串。

### 13.2.3 `std::type_index`：可作为容器键的类型包装器

`std::type_info` 对象不能直接复制，也不能直接放进 `std::unordered_map` 做键（因为它没有合适的 `std::hash` 特化）。C++11 提供了 `std::type_index`（`<typeindex>`），它是 `std::type_info` 的一个轻量包装器，可以复制、可以比较、可以做 `unordered_map` 的键。

```cpp
// type_index_basic.cpp
#include <iostream>
#include <typeindex>
#include <unordered_map>
#include <string>
#include <vector>

int main() {
    std::unordered_map<std::type_index, std::string> type_names;

    type_names[typeid(int)] = "整数";
    type_names[typeid(double)] = "浮点数";
    type_names[typeid(std::string)] = "字符串";

    int x = 0;
    auto it = type_names.find(typeid(x));
    if (it != type_names.end()) {
        std::cout << "int 对应的名字是：" << it->second << '\n';
    }
}
```

输出：

```
int 对应的名字是：整数
```

`std::type_index` 常用于：实现简单的类型注册表、运行期类型分发、反射风格的小工具等。但要注意，RTTI 和 `typeid` 会增加二进制体积，且在一些性能极度敏感或禁用异常的环境下（如内核、嵌入式）可能被禁用（编译选项 `-fno-rtti`）。

> **小结**：`std::initializer_list` 是花括号初始化的底层载体，不拥有元素，只读；`std::type_info` 通过 `typeid` 获取运行期类型信息，需配合虚函数才能做多态查询；`std::type_index` 是 `type_info` 的可复制、可哈希包装器，适合做容器键。

## 13.3 实现属性查询与特性测试宏

### 13.3.1 为什么需要特性测试宏

第 1 章已经介绍过 `__cplusplus` 和 `__cpp_*` / `__cpp_lib_*` 特性测试宏。本章把它们放在“语言支持库”的语境下再系统梳理一遍，并加上 `__has_include`。

跨平台 C++ 代码经常遇到这种情况：“我想用 C++20 的 `std::format`，但旧编译器没有；我想用某个头文件，但不确定目标系统是否提供。”如果靠猜测编译器版本（如 `#if __GNUC__ >= 13`），既不优雅也不准确。标准提供了两种更可靠的探测手段：

1. **特性测试宏**：形如 `__cpp_xxx`（语言特性）和 `__cpp_lib_xxx`（标准库特性），展开为特性并入标准工作草案的年月，如 `202002L`；
2. **`__has_include`**：询问预处理器某个头文件是否存在。

### 13.3.2 `__cpp_*` 与 `__cpp_lib_*` 宏

语言特性宏由编译器预定义，不需要包含头文件即可使用；标准库特性宏通常通过 `<version>` 头文件提供，各相关头文件也会定义。

```cpp
// feature_macros_basic.cpp
#include <iostream>
#include <version>

int main() {
    std::cout << "__cplusplus = " << __cplusplus << '\n';

#ifdef __cpp_concepts
    std::cout << "支持概念（concepts），值为 " << __cpp_concepts << '\n';
#else
    std::cout << "不支持概念\n";
#endif

#ifdef __cpp_lib_format
    std::cout << "支持 std::format，值为 " << __cpp_lib_format << '\n';
#else
    std::cout << "不支持 std::format\n";
#endif

#ifdef __cpp_lib_print
    std::cout << "支持 std::print，值为 " << __cpp_lib_print << '\n';
#else
    std::cout << "不支持 std::print\n";
#endif
}
```

如果你想判断某个特性是否“足够新”，可以把宏的值和标准规定的年月比较：

```cpp
#if defined(__cpp_lib_format) && __cpp_lib_format >= 201907L
    #include <format>
    #define HAS_FORMAT 1
#else
    #define HAS_FORMAT 0
#endif
```

第 1 章的表格里已经列出了常用的 `__cpp_*` 和 `__cpp_lib_*` 宏，这里不再重复，遇到具体特性时查表即可。

### 13.3.3 `__has_include`：探测头文件是否存在

`__has_include` 是 C++17 引入的预处理运算符，语法是 `__has_include(<header>)` 或 `__has_include("header")`，返回 1 或 0。

```cpp
// has_include_basic.cpp
#include <iostream>

#if __has_include(<optional>)
#    include <optional>
#    define HAVE_OPTIONAL 1
#else
#    define HAVE_OPTIONAL 0
#endif

#if __has_include(<filesystem>)
#    include <filesystem>
#    define HAVE_FILESYSTEM 1
#else
#    define HAVE_FILESYSTEM 0
#endif

int main() {
    std::cout << "HAVE_OPTIONAL = " << HAVE_OPTIONAL << '\n';
    std::cout << "HAVE_FILESYSTEM = " << HAVE_FILESYSTEM << '\n';
}
```

`__has_include` 的优势是：你不需要知道编译器叫什么、版本是多少，只关心“这个头文件能不能找到”。它和特性测试宏可以配合使用，形成更稳健的跨平台代码。

### 13.3.4 跨平台条件编译的典型写法

把特性测试宏和 `__has_include` 组合起来，可以写出“能力探测 + 降级”的跨平台代码：

```cpp
// cross_platform_adapter.cpp
#include <iostream>
#include <version>

#if defined(__cpp_lib_format) && __cpp_lib_format >= 201907L
#    include <format>
#    define USE_STD_FORMAT 1
#elif __has_include(<format>)
#    include <format>
#    define USE_STD_FORMAT 1
#else
#    define USE_STD_FORMAT 0
#endif

#if USE_STD_FORMAT
void print_info(const std::string& name, int age) {
    std::cout << std::format("姓名：{}，年龄：{}\n", name, age);
}
#else
void print_info(const std::string& name, int age) {
    std::cout << "姓名：" << name << "，年龄：" << age << '\n';
}
#endif

int main() {
    print_info("张三", 25);
}
```

这段代码的含义是：优先用标准 `std::format`，如果标准库没提供，就退回到传统的 `cout` 拼接。同一份源码在新旧编译器上都能编译，且无需修改。

### 13.3.5 特性测试宏 vs `__has_include`：怎么选

| 探测对象 | 推荐手段 | 示例 |
|---|---|---|
| 编译器支持某语言特性（如概念、模块） | `__cpp_xxx` 宏 | `__cpp_concepts` |
| 标准库支持某设施（如 `std::format`、`std::expected`） | `__cpp_lib_xxx` 宏 | `__cpp_lib_format` |
| 某个头文件是否存在 | `__has_include` | `__has_include(<optional>)` |
| 基准标准版本 | `__cplusplus` | `__cplusplus >= 202002L` |

> **反例**：不要写 `#if defined(__GNUC__) && __GNUC__ >= 11` 来猜测“ GCC 11 一定支持某特性”。编译器版本号和特性支持不是一一对应的（不同发行版打补丁不同，Clang/GCC/MSVC 号体系也不同）。应该查该特性对应的 `__cpp_*` 宏。

> **小结**：`__cpp_*` / `__cpp_lib_*` 宏探测语言和标准库特性，`<version>` 头文件集中提供库特性宏；`__has_include` 探测头文件是否存在；两者配合可写出“能力探测 + 降级”的跨平台代码，优于猜测编译器版本。

## 本章小结

本章我们学习了语言支持库的核心设施：

1. **`std::numeric_limits<T>`**：查询类型的极限值（最大值、最小值、精度、是否有符号等），所有成员是 `static constexpr`，可在编译期使用；
2. **固定宽度整数**：`<cstdint>` 提供 `std::int32_t`、`std::uint64_t` 等，适合二进制协议和跨平台交换；
3. **固定宽度浮点**：C++23 引入 `std::float32_t`/`float64_t` 等，当前属前瞻，编译器支持有限；
4. **`<climits>`/`<cfloat>`**：C 遗留宏，现代代码优先 `std::numeric_limits`；
5. **`std::initializer_list`**：花括号初始化的底层载体，不拥有元素、只读，常用作构造函数参数；
6. **`std::type_info`**：通过 `typeid` 获取运行期类型信息，需配合虚函数才能做多态查询；
7. **`std::type_index`**：`type_info` 的可复制、可哈希包装器，适合做 `unordered_map` 的键；
8. **特性测试宏**：`__cpp_*`（语言）和 `__cpp_lib_*`（标准库）宏，探测具体特性支持情况；
9. **`__has_include`**：探测头文件是否存在，与特性测试宏配合实现“能力探测 + 降级”。

选型口诀：**想知道类型极限用 `numeric_limits`；二进制交换用 `cstdint` 固定宽度类型；运行期判类型用 `typeid` + `type_index`；写跨平台代码用特性测试宏和 `__has_include`，不要猜编译器版本。**

下一章（第 14 章）我们进入诊断库，学习 `assert`、`errno`、`std::error_code`、标准异常层次、异常安全以及 C++23 的 `std::stacktrace`。

## 练习

1. 写一个程序，打印 `int`、`long`、`long long`、`double`、`long double` 的 `numeric_limits` 极限值，并与 `<climits>` 里的 `INT_MAX`、`LLONG_MAX` 等宏对比。
2. 用 `std::int32_t` 和 `std::uint64_t` 定义变量，赋值后打印其 `sizeof`，验证是固定宽度。
3. 写一个带虚函数的基类和两个派生类，用基类指针指向派生类对象，用 `typeid` 打印静态类型和动态类型。
4. 用 `std::type_index` 作为 `std::unordered_map` 的键，建立类型到名称的映射，查询 `int`、`double`、`std::string` 对应的名称。
5. 写一个跨平台适配示例：用 `__has_include` 和 `__cpp_lib_optional` 探测是否支持 `std::optional`，支持则用 `std::optional`，否则退回到自定义的简单 `Optional` 结构体。
