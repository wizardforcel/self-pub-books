# 第 31 章 跨标准版本演进地图

C++ 自 C++11 以来大约每三年发布一个新标准，每一版都带来新的语言特性和标准库设施。对于工程团队来说，关键问题不只是“新特性有哪些”，而是“从当前版本迁移到新版本的优先顺序是什么”、“旧代码需要改哪些地方”、“新旧代码能否混合编译”。

本章是第五篇的收官章，覆盖：

- 31.1 C++11/14/17/20/23/26 特性对照与迁移策略：各版本关键特性综合对照表，以及从 C++11 向 C++20/23 迁移的优先顺序和建议。

### 31.1.3 从 C++11 向 C++20/23 迁移的优先顺序

现有项目大多起步于 C++11 或 C++14，向 C++20/23 迁移不能一步到位，建议按以下优先顺序进行：

#### 第一阶段：零成本或低成本的“语法升级”（不改变行为，只改写法）

这些改动可以在不升级编译器标准版本的前提下部分进行，或在升级到 C++17/C++20 后立即进行：

1. **把 `NULL` 替换为 `nullptr`**：避免 `NULL` 与整数 0 的歧义；
2. **把原始 `for` 循环改写为范围基于 for 循环**：只要容器支持 `begin()`/`end()`；
3. **把 `std::bind` 改写为 Lambda**：Lambda 更可读，且能配合 `std::move` 捕获；
4. **把手动 `new`/`delete` 改写为 `std::make_unique` / `std::make_shared`**：消除手动内存管理；
5. **把 `std::random_shuffle` 替换为 `std::shuffle` + 随机数引擎**：`std::random_shuffle` 在 C++17 已移除；
6. **把 `std::auto_ptr` 替换为 `std::unique_ptr`**：`std::auto_ptr` 在 C++17 已移除；
7. **把 `typedef` 改写为 `using` 别名**：`using` 更易读，支持模板别名。

#### 第二阶段：升级到 C++17，启用“现代 C++ 基础”

在编译器支持 C++17 后，优先启用以下特性，它们带来最直接的代码质量提升：

1. **`std::optional` / `std::variant` / `std::any`**：替代手写的“指针可能为空”或“出参标志位”模式；
2. **`std::string_view`**：作为只读字符串函数参数，避免不必要的 `std::string` 拷贝；
3. **`if constexpr`**：替代复杂的 SFINAE 和标签分发，让模板代码更可读；
4. **结构化绑定**：替代 `std::get<0>(t)` 等下标访问；
5. **`std::filesystem`**：替代平台相关的文件操作 API（如 POSIX `opendir` / Windows `FindFirstFile`）；
6. **`std::scoped_lock`**：一次性锁住多个互斥量，替代手动锁顺序约定；
7. **`std::shared_mutex`**：读多写少场景下替代 `std::mutex`。

#### 第三阶段：升级到 C++20，启用“范围与模块”的大变革

C++20 是自 C++11 以来最大的语言演进，迁移收益高但改动也较大：

1. **`std::ranges` 算法 + 视图**：替代手写循环和中间容器，写出声明式的数据处理管道；
2. **`std::format` / `std::print`**：替代 `std::cout <<` 流式拼接和 C 风格 `sprintf`；
3. **概念（`concepts`）**：给模板参数加上显式约束，错误信息更清晰，接口契约更明确；
4. **`std::jthread` + 停止令牌**：替代手动 `join`/`detach` 和粗暴的线程取消；
5. **模块（`module` / `import`）**：在新模块中逐步替代头文件，但需确认构建系统（CMake 3.24+）和编译器支持；
6. **`std::chrono` 日历与时区**：替代 `boost::date_time` 或平台相关的日期处理代码。

#### 第四阶段：升级到 C++23，启用“体验优化”

C++23 主要是对 C++20 的补短板和体验优化，迁移优先级相对较低：

1. **`std::expected`**：替代“返回 `std::optional` + 单独错误码”的模式，让“值或错误”更类型安全；
2. **`std::print` / `std::println`**：替代 `std::format` + `std::cout`，更简洁；
3. **`std::stacktrace`**：增强崩溃报告和日志；
4. **`std::flat_map` / `std::flat_set`**：在读多写少的场景下替代 `std::map` / `std::set`，获得更好的缓存局部性；
5. **`std::generator`**：编写惰性序列，替代手写迭代器或协程模板。

#### 第五阶段：C++26 前瞻，谨慎试点

C++26 内容（契约、反射、`std::execution`、危险指针/RCU、基础线性代数、SIMD）在写本书时仍在标准化或编译器实验阶段，建议：

- 只在非核心、非生产代码中试点；
- 标注“前瞻”，避免在核心业务逻辑中依赖；
- 关注编译器发布说明，随标准定稿后再评估是否正式采用。

### 31.1.4 迁移时的常见陷阱

| 陷阱 | 说明 | 建议 |
|---|---|---|
| 假设 `__cplusplus` 就能准确反映特性支持 | 不同编译器对 `__cplusplus` 的更新不一致，且标准库特性不完全对应 | 用 `__cpp_*` / `__cpp_lib_*` 特性测试宏 + `__has_include` 探测能力（第 1 章、13 章） |
| C++20 模块与旧头文件混用导致宏泄漏或重复定义 | 模块里不小心 `include` 了带宏的头文件 | 用全局模块片段隔离，模块内部尽量不泄漏宏（第 6、29 章） |
| `std::string_view` 指向短生命周期的临时对象 | 返回指向局部 `std::string` 的 `string_view` 会悬空 | 函数返回值用 `std::string`，参数只读用 `string_view`（第 10 章） |
| 并行算法（`std::execution::par`）对非线程安全的操作对象并行化 | 导致数据竞争 | 确保并行算法的操作对象是线程安全的，或只用于只读场景（第 19 章） |
| `std::optional` / `std::variant` 访问无值或错误类型 | 抛出 `bad_optional_access` / `bad_variant_access` | 访问前用 `has_value()` / `holds_alternative()` 判断，或用 `value_or`（第 8 章） |

### 31.1.5 迁移检查清单

团队决定升级标准版本时，可按以下清单逐项核对：

- [ ] 编译器版本是否支持目标标准（GCC/Clang/MSVC 版本号）？
- [ ] 标准库实现是否支持目标标准的库特性？
- [ ] 构建系统（CMake）是否需要升级版本（如模块需 3.24+）？
- [ ] `CMAKE_CXX_STANDARD` 是否已更新？
- [ ] 代码中是否仍用已移除的特性（如 `std::auto_ptr`、`std::random_shuffle`、`std::bind1st/2nd`）？
- [ ] 是否有可以替换为 `std::optional`/`std::variant`/`std::string_view` 的手写模式？
- [ ] 是否有可以替换为 `std::ranges` 算法的手写循环？
- [ ] 测试是否覆盖了新旧标准混合编译的场景？
- [ ] CI 是否在新旧标准下都跑了一遍完整测试？

> **小结**：C++ 标准大约每三年一版，从 C++11 到 C++26 每一版都有明确的侧重点。迁移时建议“先语法升级，再 C++17 基础，再 C++20 大变革，再 C++23 体验优化，C++26 前瞻谨慎试点”；用特性测试宏探测能力而非猜编译器版本；注意 `string_view` 生命周期、并行算法线程安全、`optional`/`variant` 访问安全等常见陷阱。

## D. CMake 命令参考

| 类别 | 命令 | 用途 | 关键参数 / 备注 |
|---|---|---|---|
| 项目初始化 | `cmake_minimum_required` | 声明最低 CMake 版本 | `VERSION <min>` |
| | `project` | 声明项目名称、版本、语言 | `VERSION`、`LANGUAGES`、`DESCRIPTION` |
| | `cmake_policy` | 管理策略设置 | `SET` / `PUSH` / `POP` |
| 目标创建 | `add_executable` | 创建可执行目标 | 目标名、源文件列表 |
| | `add_library` | 创建库目标 | `STATIC` / `SHARED` / `MODULE` / `INTERFACE` |
| | `add_custom_target` | 创建无输出的自定义目标 | 常用于代码生成、文档构建 |
| 目标属性 | `target_sources` | 为目标指定源文件 | 可与 `PUBLIC` / `PRIVATE` / `INTERFACE` 搭配 |
| | `target_include_directories` | 为目标指定头文件路径 | 支持 `BUILD_INTERFACE` / `INSTALL_INTERFACE` |
| | `target_compile_definitions` | 为目标指定预处理宏 | 替代 `add_definitions` |
| | `target_compile_options` | 为目标指定编译器选项 | 替代 `add_compile_options` |
| | `target_compile_features` | 为目标指定所需 C++ 标准特性 | `cxx_std_20` 等 |
| | `target_link_libraries` | 为目标指定链接库 | 支持 `PUBLIC` / `PRIVATE` / `INTERFACE` |
| | `target_link_options` | 为目标指定链接器选项 | 与 `target_compile_options` 对称 |
| | `target_precompile_headers` | 为目标指定预编译头 | 优化编译时间，谨慎使用 |
| 目标查询与设置 | `get_target_property` | 读取目标属性 | 可与任意属性名配合 |
| | `set_target_properties` | 设置目标属性 | 如 `OUTPUT_NAME`、`CXX_STANDARD` |
| 依赖与包管理 | `find_package` | 查找已安装的包 | `REQUIRED`、`COMPONENTS`、`CONFIG` / `MODULE` |
| | `FetchContent_MakeAvailable` | 下载并纳入构建树 | CMake 3.14+ |
| | `add_subdirectory` | 将子目录纳入构建 | 常用于 vendored 依赖 |
| | `install` | 定义安装规则 | `TARGETS`、`EXPORT`、`FILES`、`DIRECTORY` |
| | `install(EXPORT)` | 导出目标供 `find_package` 使用 | 与 `export()` 配合 |
| 预设与构建 | `CMakePresets.json` | 项目级配置/构建/测试预设 | `configurePresets` / `buildPresets` / `testPresets` |
| | `CMakeUserPresets.json` | 开发者本地覆盖预设 | 不纳入版本控制 |
| | `cmake --preset` | 按预设配置 | `cmake --preset <name>` |
| | `cmake --build --preset` | 按预设构建 | `cmake --build --preset <name>` |
| | `ctest --preset` | 按预设运行测试 | `ctest --preset <name>` |
| 变量与缓存 | `set` | 设置普通变量或缓存变量 | `CACHE`、`PARENT_SCOPE` |
| | `option` | 声明布尔选项 | `option(<name> "<desc>" <default>)` |
| | `CMAKE_TOOLCHAIN_FILE` | 指定工具链文件 | vcpkg 集成入口 |
| | `CMAKE_EXPORT_COMPILE_COMMANDS` | 导出编译命令数据库 | 供 clang-tidy / IDE 使用 |
| 条件与循环 | `if` / `elseif` / `else` / `endif` | 条件分支 | 支持 `DEFINED`、`TARGET`、`STREQUAL` 等 |
| | `foreach` / `endforeach` | 遍历列表 | `IN LISTS`、`RANGE` |
| | `while` / `endwhile` | 条件循环 | 谨慎使用，优先用 CMake 列表操作 |

**常用生成器表达式：**

| 表达式 | 含义 |
|---|---|
| `$<CONFIG:Debug>` | 当前构建类型为 Debug 时为真 |
| `$<CXX_COMPILER_ID:GNU>` | C++ 编译器为 GCC 时为真 |
| `$<BUILD_INTERFACE:...>` | 仅在构建树中有效 |
| `$<INSTALL_INTERFACE:...>` | 仅在安装后有效 |
| `$<IF:condition,true_value,false_value>` | 条件表达式 |
