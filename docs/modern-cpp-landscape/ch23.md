# 第 23 章 Boost 容器与数据结构

标准库容器（`vector`、`map`、`unordered_map` 等）能覆盖绝大多数场景，但有些特殊需求标准库表达不方便或效率不够：比如一个对象需要同时按多个字段快速查找、对象生命周期由外部管理而容器不应额外分配内存、需要双向映射（键可值亦可键）、需要固定大小的环形缓冲等。Boost 提供了一组专门的容器来填补这些空白。

本章覆盖：

- 23.1 `boost::multi_index`：多索引容器；
- 23.2 `boost::intrusive`：侵入式容器；
- 23.3 `boost::container` 与 `boost::circular_buffer`；
- 23.4 `boost::bimap`、`boost::variant2` 与 `boost::any`。

每一节都会标注该设施的定位：**已被标准化 / 部分标准化 / 纯 Boost 独有**。

> **工具约定**：示例默认采用 CMake + vcpkg 工程模板，Boost 依赖通过 vcpkg 清单引入。代码片段可用 `cxxsh` 单文件验证（需链接对应 compiled Boost 库时按平台添加库路径），放入真实项目时请套用第 7.7 节的工程模板。

## 23.1 `boost::multi_index`：多索引容器

### 23.1.1 什么是多索引容器

在实际业务中，同一组数据常常需要按多个字段查找。例如员工表，既要能按员工 ID 查，又要能按姓名查，还要能按入职日期范围查。标准库没有直接支持“一个容器维护多个索引”的容器，传统做法是维护多个 `std::map`/`std::unordered_map` 并手动保持同步，既繁琐又易出错。

`boost::multi_index_container`（`<boost/multi_index_container.hpp>`）解决了这个问题：它在一个容器里存储一份数据，同时维护多个索引，每个索引对应一个访问路径。增删元素时，所有索引自动同步，不用手动维护一致性。

定位：**纯 Boost 独有**（标准库没有直接对应的多索引容器）。

### 23.1.2 基本用法

```cpp
// multi_index_basic.cpp
// 需要链接 Boost.MultiIndex（header-only，无需链接库文件）
#include <iostream>
#include <string>
#include <boost/multi_index_container.hpp>
#include <boost/multi_index/ordered_index.hpp>
#include <boost/multi_index/member.hpp>
#include <boost/multi_index/hashed_index.hpp>

using namespace boost::multi_index;

struct Employee {
    int id;
    std::string name;
    int age;
};

// 定义多索引容器：
// 索引 0：按 id 排序（ordered_unique，id 唯一）
// 索引 1：按 name 排序（ordered_non_unique，名字可重复）
// 索引 2：按 age 建哈希索引（hashed_non_unique）
using EmployeeContainer = multi_index_container<
    Employee,
    indexed_by<
        ordered_unique<tag<struct id_tag>, member<Employee, int, &Employee::id>>,
        ordered_non_unique<tag<struct name_tag>, member<Employee, std::string, &Employee::name>>,
        hashed_non_unique<tag<struct age_tag>, member<Employee, int, &Employee::age>>
    >
>;

int main() {
    EmployeeContainer employees;

    employees.insert({1, "张三", 25});
    employees.insert({2, "李四", 30});
    employees.insert({3, "王五", 25});

    // 按 id 查找（索引 0）
    auto& id_index = employees.get<0>();
    auto it = id_index.find(2);
    if (it != id_index.end()) {
        std::cout << "id=2 的员工：" << it->name << ", " << it->age << "岁\n";
    }

    // 按名字查找（索引 1）
    auto& name_index = employees.get<1>();
    auto name_it = name_index.find("张三");
    if (name_it != name_index.end()) {
        std::cout << "名字=张三 的员工 id：" << name_it->id << "\n";
    }

    // 按年龄范围查找（索引 2，哈希索引不支持范围查询，这里仅演示 get<2>）
    auto& age_index = employees.get<2>();
    std::cout << "年龄为 25 岁的员工个数：" << age_index.count(25) << "\n";
}
```

输出：

```
id=2 的员工：李四, 30岁
名字=张三 的员工 id：1
年龄为 25 岁的员工个数：2
```

### 23.1.3 关键特性

- **一份数据，多个索引**：元素只存储一份，各个索引只存迭代器/句柄，内存开销比手动维护多个容器小；
- **自动同步**：插入或删除一个元素，所有索引自动更新，不会出现“这个 map 里有，那个 map 里没有”的不一致；
- **索引类型丰富**：`ordered_unique`、`ordered_non_unique`（红黑树，有序）、`hashed_unique`、`hashed_non_unique`（哈希表，无序）、`random_access`（按位置访问）、`sequential`（按插入顺序）等。

### 23.1.4 选型建议

| 需求 | 推荐 | 原因 |
|---|---|---|
| 同一数据需按多个字段查找 | `boost::multi_index_container` | 避免手动维护多个容器同步 |
| 只需按单字段查找 | `std::map` / `std::unordered_map` | 标准库，更轻量 |
| 需要范围查询 | 用 `ordered_unique`/`ordered_non_unique` 索引 | 哈希索引不支持范围查询 |

> **反例**：不要为了“可能有一天要按多个字段查”而把所有表都上 `multi_index`。如果只查一个字段，标准 `std::map`/`std::unordered_map` 更简单、编译更快。

## 23.2 `boost::intrusive`：侵入式容器

### 23.2.1 什么是侵入式容器

普通容器（如 `std::list`）在内部为每个元素分配一个节点，节点里除了存用户数据，还存前驱/后继指针。这意味着元素在容器内外是两份内存：用户对象自己管理，容器节点由容器管理。

**侵入式容器（intrusive container）** 则相反：用户类型自己包含链表节点成员（前驱/后继指针），容器直接操作这些成员，不额外分配节点内存。容器不拥有元素的生命周期，元素的创建和销毁由用户负责，容器只负责把已存在的对象串联起来。

定位：**纯 Boost 独有**（标准库没有侵入式容器）。

### 23.2.2 基本用法

```cpp
// intrusive_basic.cpp
// 需要链接 Boost.Intrusive（header-only，无需链接库文件）
#include <iostream>
#include <boost/intrusive/list.hpp>

using namespace boost::intrusive;

// 用户类型自己包含 list 成员钩子
struct Employee {
    list_member_hook<> hook;  // 侵入式钩子，列表节点就存在这里
    int id;
    std::string name;

    Employee(int i, std::string n) : id(i), name(std::move(n)) {}
};

// 定义侵入式列表
using EmployeeList = list<Employee, member_hook<Employee, list_member_hook<>, &Employee::hook>>;

int main() {
    EmployeeList list;

    Employee e1(1, "张三");
    Employee e2(2, "李四");
    Employee e3(3, "王五");

    // 将已存在的对象插入列表（不分配新节点）
    list.push_back(e1);
    list.push_back(e2);
    list.push_back(e3);

    for (const auto& e : list) {
        std::cout << e.id << ": " << e.name << '\n';
    }

    // 删除时只需从列表移除，对象本身由外部管理
    list.erase(list.begin());
    std::cout << "删除 e1 后，列表大小：" << list.size() << '\n';
}
```

输出：

```
1: 张三
2: 李四
3: 王五
删除 e1 后，列表大小：2
```

### 23.2.3 优缺点与适用场景

优点：
- **无额外分配**：不需要为每个元素单独分配节点内存，适合内存紧张或对分配极度敏感的场景（嵌入式、内核、高频交易）；
- **缓存友好**：元素和节点在一起，没有额外的节点指针间接寻址；
- **生命周期解耦**：容器不拥有元素，元素可以同时在多个侵入式容器中（如一个对象既在链表 A 又在链表 B）。

缺点：
- **用户类型侵入**：类里必须包含钩子成员，污染了类设计；
- **生命周期责任在用户**：容器析构时不会销毁元素，如果元素先被销毁而还在容器里，会悬空；
- **不能和标准算法混用**：侵入式容器的迭代器不一定满足标准容器的全部要求。

适用场景：内核模块、嵌入式系统、游戏实体管理、高频交易订单簿等对分配敏感、且元素生命周期由外部明确管理的场景。

> **反例**：日常业务开发中不要用侵入式容器，除非你有明确的性能或内存证据表明标准容器的节点分配是瓶颈。侵入式容器牺牲了代码简洁性和安全性，换取运行期微小收益，滥用会得不偿失。

## 23.3 `boost::container` 与 `boost::circular_buffer`

### 23.3.1 `boost::container`：扩展容器

`boost::container`（`<boost/container/vector.hpp>`、`<boost/container/deque.hpp>` 等）提供了标准容器的扩展版本，如 `boost::container::vector`、`boost::container::deque`、`boost::container::flat_map`、`boost::container::flat_set`。它们在标准容器基础上增加了一些特性：

- 构造时可指定内存分配策略；
- 支持小对象优化（small object optimization），小容量时使用内置缓冲区避免堆分配；
- 一些标准库尚未加入的成员函数。

不过，C++17/20/23 的标准库已经大幅补齐了容器功能（如 `std::vector` 小对象优化在某些实现中已有、C++23 的 `std::flat_map`/`std::flat_set`），`boost::container` 的必要性在下降。

定位：**部分标准化**（标准库有对应容器，Boost 版本是扩展和超集）。

### 23.3.2 `boost::circular_buffer`：环形缓冲区

`boost::circular_buffer`（`<boost/circular_buffer.hpp>`）是一个固定容量的环形缓冲区：当缓冲区满了，新元素会自动覆盖最旧的元素。适合“固定大小的滑动窗口”“最近 N 条日志”“固定窗口的移动平均”等场景。

定位：**纯 Boost 独有**（标准库没有环形缓冲容器）。

```cpp
// circular_buffer_basic.cpp
// 需要链接 Boost.Container（header-only，无需链接库文件）
#include <iostream>
#include <boost/circular_buffer.hpp>

int main() {
    boost::circular_buffer<int> cb(3);  // 容量 3

    cb.push_back(1);  // [1]
    cb.push_back(2);  // [1, 2]
    cb.push_back(3);  // [1, 2, 3]（满了）
    cb.push_back(4);  // [4, 2, 3]（覆盖最旧的 1）

    std::cout << "缓冲区内容：";
    for (int x : cb) {
        std::cout << x << ' ';
    }
    std::cout << '\n';

    std::cout << "最新元素：" << cb.back() << '\n';   // 4
    std::cout << "最旧元素：" << cb.front() << '\n';   // 2
}
```

输出：

```
缓冲区内容：4 2 3 
最新元素：4
最旧元素：2
```

`boost::circular_buffer` 支持随机访问、`front()`/`back()`、`push_back()`/`push_front()`、`pop_back()`/`pop_front()`，容量固定，满时自动覆盖。

### 23.3.3 选型建议

| 需求 | 推荐 | 原因 |
|---|---|---|
| 固定容量滑动窗口，满时覆盖最旧 | `boost::circular_buffer` | 专门为这个场景设计，标准库无直接对应 |
| 标准容器功能不足，需要扩展特性 | `boost::container` | 标准库容器通常已足够，优先标准 |
| 需要 C++23 前才用 flat_map/flat_set | `boost::container::flat_map` | C++23 起用 `std::flat_map`/`std::flat_set` |

## 23.4 `boost::bimap`、`boost::variant2` 与 `boost::any`

### 23.4.1 `boost::bimap`：双向映射

`boost::bimap`（`<boost/bimap.hpp>`）是一种双向映射容器：既可以按键查值，也可以按值查键，两个方向都快速。标准库 `std::map` 只支持单向（键→值），要反向查找需要遍历或维护第二个 map。

定位：**纯 Boost 独有**（标准库没有双向映射容器）。

```cpp
// bimap_basic.cpp
// 需要链接 Boost.Bimap（header-only，无需链接库文件）
#include <iostream>
#include <boost/bimap.hpp>

int main() {
    using namespace boost::bimaps;

    // bimap<左侧类型, 右侧类型>
    bimap<std::string, int> name_to_age;

    name_to_age.insert({"张三", 25});
    name_to_age.insert({"李四", 30});

    // 按名字查年龄
    auto it1 = name_to_age.left.find("张三");
    if (it1 != name_to_age.left.end()) {
        std::cout << "张三的年龄：" << it1->second << '\n';
    }

    // 按年龄查名字
    auto it2 = name_to_age.right.find(30);
    if (it2 != name_to_age.right.end()) {
        std::cout << "30岁的姓名：" << it2->second << '\n';
    }
}
```

输出：

```
张三的年龄：25
30岁的姓名：李四
```

### 23.4.2 `boost::variant2`：支持 valueless-by-exception 的 variant

`boost::variant2`（`<boost/variant2/variant.hpp>`）是 Boost 对 `std::variant` 的改进版本，主要区别在于支持 **valueless-by-exception** 策略：当 `std::variant` 因异常导致无法保存任何值时，`boost::variant2` 可以进入“无值”状态，而不是终止程序。

定位：**部分标准化**（标准库有 `std::variant`，Boost 版本是扩展）。

C++20 起 `std::variant` 已足够好用，除非有特殊的异常安全需求，否则优先 `std::variant`。

### 23.4.3 `boost::any`：运行期任意类型

`boost::any`（`<boost/any.hpp>`）是 `std::any` 的 Boost 前身，用法和 `std::any` 几乎一样：存放任意类型的值，取出时用 `boost::any_cast<T>`。

定位：**已被标准化**（C++17 `std::any`）。新代码优先用 `std::any`，`boost::any` 仅用于旧项目兼容。

## 本章小结

本章我们学习了 Boost 容器与数据结构：

1. **`boost::multi_index_container`**：纯 Boost 独有，一个容器维护多个索引，适合同一数据按多个字段查找，自动同步所有索引；
2. **`boost::intrusive`**：纯 Boost 独有，侵入式容器不额外分配节点，适合内存敏感且元素生命周期由外部管理的场景，但类设计会被侵入；
3. **`boost::container`**：部分标准化，标准容器的扩展版本；`boost::circular_buffer` 纯 Boost 独有，固定容量环形缓冲，满时覆盖最旧元素；
4. **`boost::bimap`**：纯 Boost 独有，双向映射，可按键查值也可按值查键；
5. **`boost::variant2`**：部分标准化，`std::variant` 的改进版，支持 valueless-by-exception；
6. **`boost::any`**：已被标准化，新代码优先 `std::any`。

选型口诀：**多字段查同一数据用 `multi_index`；内存极度敏感且生命周期外部管理用 `intrusive`；固定窗口覆盖最旧用 `circular_buffer`；双向查找用 `bimap`；否则优先标准库容器。**
